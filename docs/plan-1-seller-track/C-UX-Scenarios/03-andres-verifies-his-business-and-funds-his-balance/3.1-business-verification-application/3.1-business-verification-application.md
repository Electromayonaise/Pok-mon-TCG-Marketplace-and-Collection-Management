## Overview

**Page Purpose:** Collect Andrés's legal identity and external-presence proof for business verification (FR-S5).

**User Situation:** He's run an informal Instagram card shop for a while and wants TEZG's Verified Business status. Sits down at his desktop with his documents ready — this is a deliberate, unhurried task, not a glance-and-go one.

**Mental State:** Slight apprehension about paperwork, but motivated — verification unlocks the commission-balance/business-listing capabilities he wants.

**Success Criteria:** Application submitted with all required fields; he's told clearly what happens next (manual review, no fixed SLA).

**Entry Points:**
- Account menu → "Apply for Business Verification."

**Exit Points:**
- → 3.2 Application Status (Pending), on submit.

## Page States

| State | When | Appearance | Actions |
|-------|------|------------|---------|
| Default | Page loads | Fields empty, button disabled | Fill fields |
| Ready | All fields valid | Button enabled | Submit |
| Submitting | Submit tapped | Button disabled | None |

| Error — network/server | Request fails | Inline error above the form: "Couldn't submit your application — check your connection and try again" | Retry |
| Success | Application submitted | Navigates to 3.2 (Pending state) | — |

## Technical Notes

- No SLA or countdown is shown anywhere on this page or its confirmation — CAP-15 review is manual with no fixed timeline; the copy on 3.2 explicitly avoids implying a turnaround time.
- This form cannot be resubmitted or edited once submitted — a rejected application requires a fresh application (see 3.2), not an edit-in-place flow, since CAP-15 defines no automatic retry/resubmission path.
- If Andrés's session expires while the identity-document upload is in flight (e.g. a large file over a slow connection), the form preserves everything he's already typed or attached client-side and prompts an in-place re-authentication rather than discarding the form and bouncing him to a login screen — losing a half-completed document-heavy application to a session timeout would be a disproportionate cost for a task he's already told is a deliberate, unhurried session.
