## Overview

**Page Purpose:** Show Andrés the current state of his verification application — Pending, Approved, or Rejected (FR-S5, CAP-15).

**User Situation:** He gets a notification his status changed, or checks in periodically out of curiosity while waiting. This is a glance-and-check task, unlike 3.1's deliberate desktop session.

**Success Criteria:** He always knows exactly where his application stands, with no false impression of a fixed timeline.

**Entry Points:**
- Notification tap (status-change push).
- Account menu → "Verification status" (visible once an application exists).

**Exit Points:**
- Approved → 3.3 Commission Balance Management (first visit) or account menu.
- Pending → [1.2 Create Listing](../../01-valentina-publishes-her-first-listing/1.2-create-listing/1.2-create-listing.md) with `sellerType=business` (FR-S9 — creation is never gated on Approved status or commission balance), or account menu.
- Rejected → account menu (no further action available on this page).

## Page States

| State | When | Appearance | Actions |
|-------|------|------------|---------|
| Pending | Application submitted, no admin decision yet | Pending badge + no-SLA message, Create a Listing button shown, no Continue-to-balance button | Create a listing, wait / check back |
| Just published (Pending) | Returned here right after a successful business-side publish while still Pending | Listing Published Banner visible above the status badge | Dismiss (or auto-dismisses) |
| Approved | Admin approved | Approved badge + confirmation message, Create a Listing and Continue buttons both shown | Create a listing, continue to 3.3 |
| Rejected | Admin rejected | Rejected badge + no-resubmission-path message, no Create a Listing button | Submit a new application (returns to 3.1) |
| Error | Status fetch fails | Inline error: "Couldn't load your application status — check your connection and try again" | Retry |

---

## Technical Notes

- No polling countdown, no progress bar, no "estimated wait" copy anywhere on this page — CAP-15 has no fixed SLA and implying one here would misrepresent a manual process.
- The Rejected state's "Submit a new application" path returns to a blank 3.1, not a pre-filled edit of the rejected one — consistent with 3.1's own Technical Notes.
- The Create a Listing button is deliberately absent in the Rejected state — FR-S9's Pending/Approved carve-out never extends to a rejected application, which has no business identity to attach a listing to.
