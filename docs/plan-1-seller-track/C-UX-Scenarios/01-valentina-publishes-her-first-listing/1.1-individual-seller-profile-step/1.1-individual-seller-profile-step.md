## Overview

**Page Purpose:** Complete the one-time individual-seller profile step, with no business-paperwork gate (FR-S1).

**User Situation:** She has a card she'd rather sell or trade than keep. Taps "Start selling" from her account menu / My Sales tab for the first time.

**Mental State:** Hope — this should take one evening session, no paperwork. Worry — that TEZG will treat her like a business and demand more than a hobbyist should have to give.

**Discovery Method:** Taps "Start selling" from the My Sales tab (Buyer-track surface `4.4-my-sales-tab.md`), shown there whenever her account has zero individual-seller listings.

**Success Criteria:** Profile fields saved, account flagged as Individual Seller, Valentina proceeds straight to listing creation — no review queue, no waiting.

**Entry Points:**
- My Sales tab → "Start selling" (first time only; skipped entirely on return visits once complete).

**Exit Points:**
- → 1.2 Create Listing (on save).

## Layout Structure

Single centered column, same "one job per screen" pattern as the Buyer track's Sign Up page.

```
+--------------------------------+
|      Start selling on TEZG     |
|                                 |
|  [ Display name             ]  |
|  [ Contact preference   v  ]  |
|                                 |
|  [        Continue          ]  |
+--------------------------------+
```

Widens to a wider centered column at tablet/desktop (max ~400px) — never two-column; consistent with the Buyer track's single-purpose form pages.

## Technical Notes

- No verification, no review queue — FR-S1's testable Consequence is that the individual-seller path has zero admin-review latency, unlike Andrés's business-verification path (Scenario 03). Any future addition of a review step here would violate this FR.
- This step is skipped entirely on all subsequent listing-creation sessions once the profile exists — 1.2 becomes the direct entry point for a returning individual seller. This is decided by checking the profile-complete flag at navigation time, not by client-side session memory — so if the save succeeds but the client-side redirect to 1.2 is interrupted (e.g. connection drop right after Continue), her next visit correctly routes straight to 1.2 rather than replaying this step.
