## Overview

**Page Purpose:** Make the reservation guarantees observable:
- the unit trace (who decremented what, and how many rows changed);
- repeated concurrent races with a per-repetition tally;
- the abort-after-reserve harness;
- commission and application event injection, to see pause, withdraw and restore.

**Success Criteria:** NFR-INV-1..3 can be reproduced by clicking one preset and reading one result line.

**Entry Points:** `/dev` → INV.

**Exit Points:** 6.1 (open the losing buyer's view for a chosen repetition, with fixtures).

## Page Sections

### Section: Units Tab

**OBJECT ID:** `inv-console-units`

| Property | Value |
|----------|-------|
| Content | Search for a unit by seller/item/condition. It shows the quantity, every listing reading it (card or bundle, with the computed availability), and a trace of reservations and releases: `{at, caller (ORD/TRD/restock), delta, rowsAffected, before → after}` |
| INV-S2 proof | For the Valentina fixture after the bundle reservation: one trace row "TRD · −1 · filas afectadas 1 · 1 → 0". Both listings show availability 0 |

### Section: Race Simulator

**OBJECT ID:** `inv-console-race`

| Property | Value |
|----------|-------|
| Component | [`components.race-simulator`](../../../DESIGN.md) |
| Presets | "50 compras · última unidad" (NFR-INV-1); "25 compras + 25 intercambios · inventario compartido" (NFR-INV-2); "Lote de 20 componentes" (latency) |
| Output | A per-repetition table plus a summary line; any repetition with ≠ 1 winner, or a final quantity < 0, is highlighted in `status-error` with the words "FALLA" |

### Section: Reserve-and-Abort Harness

**OBJECT ID:** `inv-console-abort`

| Property | Value |
|----------|-------|
| Modes | "Falla al insertar el pedido" · "Error lanzado después de reservar" |
| Output | "Cantidad antes = después en {n}/{n} · 0 escrituras compensatorias · 0 filas de reserva" (NFR-INV-3) |

### Section: Events Tab

**OBJECT ID:** `inv-console-events`

| Property | Value |
|----------|-------|
| Inject | `CommissionBalanceExhausted` / `Replenished {businessId, ledgerSeq}`; `BusinessApplicationRejected` / `Approved {applicationId}` |
| Output | Per event: "aplicado" or "ignorado: ledgerSeq {n} ≤ último aplicado {m}" / "ignorado: ya procesado para {applicationId}"; the affected listings with before → after state |

## Technical Notes

- Each racer uses its own connection and transaction (NFR-INV-1). The console orchestrates through a dev-only endpoint that is absent from production builds.
- The console reads through the same `listings` public API plus the dev-only harness. It never writes a unit directly.
