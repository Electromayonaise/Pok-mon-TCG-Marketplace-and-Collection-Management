## Overview

**Page Purpose:** Publish a card, a sealed product or a bundle, attaching each item to the seller's inventory unit `(seller, item, condition)`. Seller-kind rules are applied visibly, never silently (FR-INV-1, FR-INV-2, FR-INV-7).

**Success Criteria:**
- The form adapts to the kind and the seller type.
- An existing unit is shown instead of a quantity field.
- All field errors are reported at once.
- A refused bundle names the offending item and creates nothing.

**Entry Points:** 4.2 "Nueva publicación"; 5.2 "Publicar mientras tanto"; the "Vender" bottom-bar entry; back from 1.2 with the draft restored.

**Exit Points:** 4.2 (success redirect); 1.2 (profile gate); 5.2 (rejected-business notice).

## Page Sections

### Section: Kind Selector

**OBJECT ID:** `inv-create-kind`

| Property | Value |
|----------|-------|
| Component | Radio group: Carta · Producto sellado · Lote |
| Behavior | Switching kind keeps shared fields (price, location, description) and clears kind-specific ones, with the note "Cambiaste el tipo: revisa los datos de la carta." |

### Section: Item Picker (Carta / Producto sellado)

**OBJECT ID:** `inv-create-item`

| Property | Value |
|----------|-------|
| Component | Combobox over the catalog (prefix search, as in 2.1), filtered by kind |
| Condition | Cards: NM, LP, MP, HP, DMG, each with a gloss ("NM · como nueva"). Sealed: fixed "Sellado", no selector |
| Unit lookup | After item and condition are chosen: if the unit exists, the quantity field is replaced by the note "Ya tienes {n} unidades de {carta} ({estado}). Esta publicación comparte ese inventario." Otherwise the "Cantidad" field is shown (1–999) |
| Error | `InvalidItemRef`: "No encontramos esa carta o producto en el catálogo. Búscalo de nuevo y selecciónalo de la lista." |

### Section: Bundle Builder (Lote)

**OBJECT ID:** `inv-create-bundle`

| Property | Value |
|----------|-------|
| Components | 2–20 rows `{carta, estado, ×1–4}`; "+ Agregar carta" opens the same combobox (cards and sealed products are both searchable, so the refusal can be explained) |
| Sealed guard | Adding a sealed product shows an inline `field-error` on that row: "{producto} es un producto sellado y no puede ir dentro de un lote. Quítalo o publícalo por separado." plus "Quitar del lote". The server repeats the same check (`SealedProductInBundle`) and nothing is created |
| Min / empty | 0 rows: "Agrega al menos dos cartas al lote." 1 row: the same message (RequestValidationFailed) |
| Availability | Live "Lotes disponibles: {min ⌊unidad/×⌋}", from existing units. For new units, "¿Cuántos lotes ofreces?" (1–99) sets the stock created |

### Section: Common Fields

**OBJECT ID:** `inv-create-common`

| Property | Value |
|----------|-------|
| Price | Integer COP 1.000–100.000.000 (`InvalidPrice`) |
| Location | Defaults to the seller's meeting point; "Cambiar" opens `location-picker`. Outside Colombia: `InvalidLocation` copy plus "Usar mi ubicación" |
| Description | 0–1.000 characters with a counter |
| Open to trade | Individual only: `open-to-trade-toggle`, default off. Business: no toggle; an info line "Las tiendas venden dentro de TEZG, así que sus publicaciones no se pueden abrir a intercambios." |

### Section: Business Pending Notice

**OBJECT ID:** `inv-create-pending-notice`

| Property | Value |
|----------|-------|
| Condition | Business with a `Pending` application |
| Content | `explainability-banner` (info): "Tu tienda está en revisión: esta publicación se verá sin la insignia de verificación y aún no se podrá comprar." |

## Technical Notes

- The unit lookup is a read (`listings.findUnit(seller, item, condition)`). It is advisory: the server resolves the unit at create time (FR-INV-1 rule 3), so if another tab created it meanwhile, the success confirmation says "Se unió a tu inventario existente de {n} unidades."
- The draft is kept per device for the profile-gate round trip (IDN-S2).
- `openToTrade` is never sent for business sellers. The API refusal copy exists only for crafted calls (1.1).
