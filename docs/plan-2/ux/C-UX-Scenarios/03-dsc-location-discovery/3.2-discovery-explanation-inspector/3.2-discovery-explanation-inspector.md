## Overview

**Page Purpose:** Make the discovery algorithm observable on fixtures: each row's raw distance, inclusion verdict, sort keys, explanation parts, and why excluded rows were excluded. Lets a developer flip the seller-kind stub and hidden toggles, then prove determinism.

**Success Criteria:**
- The 6 geometry fixtures reproduce the FR-DSC-2/3 acceptance at a glance.
- A seller-kind flip shows a diff of only the derived fields.
- The 10× run reports 0 ordering differences.

**Entry Points:** `/dev` index → DSC; the "Inspeccionar esta búsqueda" link on 3.1 (non-production only).

**Exit Points:** 3.1 with the same query.

## Page Sections

### Section: Query Builder

**OBJECT ID:** `dsc-inspect-query`

| Property | Value |
|----------|-------|
| Component | [`components.api-explorer-panel`](../../../DESIGN.md) with form fields mirrored to a JSON request pane |
| Presets | "Medellín 15 km (fixtures)", "Sin área", "Bogotá-only entry from Medellín" (FR-DSC-7 edge), "Área inválida (Quito)" |

### Section: Row Table

**OBJECT ID:** `dsc-inspect-rows`

| Property | Value |
|----------|-------|
| Component | `data-table`, included rows first in API order, then excluded rows |
| Columns | rank · listingId · seller · sellerKind (live) · exact distance · displayed · price · sort key tuple `(dist, price, id)` · explanation parts (typed, e.g. `[distance(12.4), pickup]`) · verdict |
| Tie marker | An inline "↳ empate…" row names the deciding key |
| Card-detail preset | Shows `hasActiveListings=false`, `listings=[]` and "La carta sigue en el resultado" in words |

### Section: Stub Controls

**OBJECT ID:** `dsc-inspect-stubs`

| Property | Value |
|----------|-------|
| Seller kind | Switch a seller's stubbed kind. On Aplicar, the query re-runs and a diff pane lists the changed fields per row (expected: `pickupAvailable`, explanation parts only) |
| Hidden toggle | Set or clear `hiddenAt` on a fixture listing. Re-run shows it under "por estado: hidden 1" |

### Section: Determinism Runner

**OBJECT ID:** `dsc-inspect-determinism`

| Property | Value |
|----------|-------|
| Behavior | "Ejecutar 10×" runs the current query 10 times and compares the orderings byte for byte. Result: "10 ejecuciones · 0 diferencias en el orden ✓", or the first diverging index in `status-error` |

## Page States

| State | When | Appearance | Actions |
|-------|------|------------|---------|
| Loading | Query running | Table skeleton; buttons disabled with "Ejecutando…" | — |
| Empty | No rows included | Table shows only excluded rows plus "0 incluidas" | Change the query |
| Error — decision | `InvalidSearchArea` | Response pane shows the Decision JSON; the form highlights the field | Fix the input |
| Error — transport | Failed | Banner plus Reintentar | Reintentar |
| Success | Results | As in the layout | Stubs, 10× |

## Technical Notes

- Reads the same `listings.browse` / `getCardDetail` as 3.1, plus a dev-only `debug=true` flag that adds exact distances, sort keys and excluded rows. The flag is rejected in production.
- The stubs act only on the fixture adapter (PRD §13 Fakes). They never write real identity data.
