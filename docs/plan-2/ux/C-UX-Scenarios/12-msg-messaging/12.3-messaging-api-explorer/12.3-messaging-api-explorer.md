## Overview

**Page Purpose:** Prove the two MSG paths on fixtures: that the contact service renders every hard name and price exactly, encodes a link that decodes back byte for byte, stays deterministic and never calls WhatsApp; and that in-app eligibility, unread counts and the compose→send race behave as specified.

**Success Criteria:**
- Every preset reports PASA only when each of its checks holds, with the observed value shown next to each check.
- The generated message is shown three ways, side by side: the rendered preview, the decoded link and the raw JSON.
- "Llamadas externas: 0" and "Teléfonos en registros: 0" are visible after every run.

**Entry Points:** The `/dev` index.

**Exit Points:** 12.1 for a fixture listing ("Abrir como Camila"); 12.2 for a fixture conversation ("Abrir como {actor}"); the `/dev` index.

### Section: Presets (Plantillas)

**OBJECT ID:** `msg-dev-presets`

| Preset | Setup | Action | Checks |
|--------|-------|--------|--------|
| **Aceptación FR-MSG-1** | A seed individual listing at $45.000 | Generate as Camila | `text` contains the exact product name and "$45.000 COP"; `externalUrl` decodes to `text` byte for byte; phone appears only in `externalUrl` |
| **Nombres difíciles** | The three fixture names: "Pokémon Center Exclusivo — Pikachu & Zekrom GX (Niñez) ⚡🔥" (73 characters); the 500-character name; the URL-like name | Generate each | URL ≤ 2.000; decode = `text`; valid UTF-8 with no broken surrogate pairs; NFC; cuts only at grapheme boundaries with "…", product name ≥ 20 graphemes; full price kept; `copyText` untruncated; URL-like text returned as plain text |
| **Intercambio máximo** | `kind: 'trade'`: 10 offered items × 200-character names, all NM, plus $20.000 | Generate | URL ≤ 2.000; "$20.000 COP" and every "(NM)" present; names shortened longest first, none below 20 graphemes. For this fixture the shortening alone fits, so no item collapses into "+{n} cartas más"; a second fixture (10 emoji-only names) exercises the collapse and shows which conditions it drops (see `review-ux-edge-cases.md`). `copyText` lists all 10 in full |
| **Determinismo ×1000** | Any preset's input | Generate 1.000 times | 1 distinct output (hash of `text`, `externalUrl`, `copyText`); p95 generation time next to the ≤ 200 ms target (NFR-MSG-1) |
| **Precios 1.000–100.000.000** | One listing per price: 1.000 · 45.000 · 999.999 · 1.000.000 · 100.000.000 | Generate each | Formatted per `ADD-§2.7` ("$1.000 COP" … "$100.000.000 COP"); no decimals; dot thousands separator |
| **Límites de contacto** | Camila with 30 contacts in the last hour; 10 with one seller today; an IP with 60 in the last hour | 31st request; 11th to the same seller; 61st from the IP | Each gets `ContactRateLimited` citing its retry time; counters unchanged by the refused request; the phone is absent from the Decision and the logs |
| **Elegibilidad** | Recipients: Approved shop · Pending shop · Rejected shop · individual seller · buyer · the caller's own shop | Start a conversation to each as Camila; then as Andrés to a new buyer | Approved → allowed; Pending → `allowedWithNotice` (`RecipientNotYetVerified`); others → `NotBusinessAccount`; own shop → refused; Andrés → `BusinessCannotInitiate` |
| **Carrera redactar→enviar ×100** | Composer open to a Pending shop | Flip the stub between compose and send: Pending → Rejected; Pending → Approved; Approved → Pending | → Rejected: `NotBusinessAccount` citing the change, text returned, **0 message rows**; → Approved: sent, `recipientVerificationAtSend = Approved`, no notice; Approved → Pending: invariant breach logged once per run. 100/100 each (NFR-MSG-4) |
| **No leídos intercalados** | A fresh conversation Camila ↔ Andrés | Scripted interleaving: C, A, A, C (open), A, A (open) … | Each side's unread count after every step equals the other party's messages after its `lastReadMessageId`; opening sets it to 0; the marker never moves back; order by `lastMessageAt` then id; delivery visible on the next poll |
| **Traspaso de intercambio** | UJ-2 terms (Pikachu ex NM + Espeon V NM, no cash) and the FR-TRD-6 acceptance terms (with $20.000) | Run `trading`'s accept through the listings fake | Exactly 1 `generateContactMessage({ kind: 'trade', … })` call per acceptance, recorded with its `tradeSummary`; the text comes from the §7 template (the cash segment dropped at $0; "$20.000 COP" when present); `trading` renders nothing |

Each preset has "Ejecutar"; the race, determinism and interleaving presets also have "Ejecutar ×100" (×1000 for determinism). Every run shows its seed, which can be pasted back to replay it.

## Technical Notes

- The console calls the real `listings.generateContactMessage` and the real `messaging` handlers. Only `identity` (switchable state) and the external app (a stub that fails the run if called) are faked, per the §17 fakes.
- The race preset flips the identity stub after the compose read and before the send command, so it exercises the send-time check (FR-MSG-5) rather than a UI guard.
- The phone scan searches for each fixture phone in its stored form and without "+", so a partial leak is caught too.
- Admin actor: `getThread` returns `ConversationNotVisibleToCaller` (A-38), which the console shows as a refusal.
- The page is excluded from production builds by route configuration; the banner is a second line of defence.
