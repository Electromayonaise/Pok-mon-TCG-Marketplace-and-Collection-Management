## Overview

**Page Purpose:** Start and monitor feed runs, audit their counts, inspect quarantined rows by reason, confirm that attribute changes kept each entry's identity, and watch TRM freshness (FR-CAT-3, FR-CAT-4, FR-CAT-7, FR-CAT-8). The Entregas tab is the system's event panel: it lists failed event deliveries and replays them, and lists deliveries stuck `pending` for more than 24 h (NFR-SYS-6; ARCHITECTURE AD-SYS-2, §7.3). The header shows when the hourly tick last ran (ARCHITECTURE §4).

**Success Criteria:** Counts add up to the rows in the file. A rerun shows convergence. A concurrent start is refused with an explanation. Every quarantined row shows its reason and raw content. Every failed delivery can be replayed from the Entregas tab. A silent hourly tick is visible in the header.

**Entry Points:** Admin rail → Catálogo; admin rail → Entregas fallidas (opens the Entregas tab); the daily-alert link (a failed scheduled run).

**Exit Points:** 2.2 (from a revision row, "Ver carta").

## Page Sections

### Section: Run Control

**OBJECT ID:** `cat-ingest-control`

| Property | Value |
|----------|-------|
| Component | File `<select>` (files staged by the feed port; no browser upload in V1) plus `button-primary` "Iniciar ingesta" |
| Behavior | Starting a run writes an audit row (NFR-SYS-8). If a run is in progress, the button is replaced by the banner "Ya hay una ingesta en curso (iniciada el {fecha}). Espere a que termine para iniciar otra." plus "Ver ingesta en curso" (`FeedRunInProgress`) |
| Progress | `role="progressbar"` with "6.420 / 10.000 filas", announced politely every 25 % |

### Section: Runs Tab

**OBJECT ID:** `cat-ingest-runs`

| Property | Value |
|----------|-------|
| Component | [`components.data-table`](../../../DESIGN.md), 25 per page, newest first |
| Columns | Run · started by (admin name or "Programada") · start → end · Creadas · Actualizadas · Sin cambios · Cuarentena · result |
| Result words | "Completa" / "Interrumpida: los lotes ya confirmados son válidos; vuelva a ejecutar para completar" / "Converge con la ejecución anterior" |
| Integrity check | If created + updated + unchanged + quarantined ≠ the file's rows: "Los conteos no suman las filas del archivo" in `status-error` text |

### Section: Quarantine Tab

| Property | Value |
|----------|-------|

| Row expand | Raw row in `typography.code`, read-only; "Copiar fila" |
| Note | "Las filas en cuarentena no se aplicaron. Corríjalas en el feed de origen y vuelva a ejecutar." |

### Section: Revisions Tab

**OBJECT ID:** `cat-ingest-revisions`

| Property | Value |
|----------|-------|
| Component | `data-table` |
| Columns | Entry (name plus `catalogEntryId`) · changed fields · before → after · run |
| Proof line | "El id de la carta no cambió: publicaciones, colecciones y listas de deseos siguen enlazadas." Each row links to 2.2 |

### Section: TRM Tab

**OBJECT ID:** `cat-ingest-trm`

| Property | Value |
|----------|-------|
| Content | Today's rate (e.g. "$4.123,45 por US$1 · vigente 1 oct 2026 · datos.gov.co"), the last fetch attempt, and the next scheduled attempt (hourly 07:17–20:17 Bogotá, best-effort; ARCHITECTURE §4) |
| Carried forward | "Sin TRM para hoy: usamos la del {día}." in `status-pending` plus words |
| Source mismatch | When a re-fetch returns a different value for a stored validity date (`FxRateSourceMismatch`, AD-CAT-3): a row in the tab's log, "La TRM del {dia} volvió con un valor distinto ({nueva}) al guardado ({guardada}). Conservamos el valor guardado; revise la fuente si el cambio persiste." in `status-pending` plus words. The stored rate is not changed |

### Section: Deliveries Tab (event panel)

**OBJECT ID:** `sys-event-deliveries`

| Property | Value |
|----------|-------|
| Component | `data-table`, 25 per page, oldest first; the tab label carries the failed count, as the rail badge does |
| Rows | `EventDelivery` rows with `status='failed'`, plus rows still `pending` more than 24 h after `createdAt`, labelled "Atascada" (shared-kernel, AD-SYS-2 rule 9) |
| Digest line | Above the table, from the latest `FailedDeliveryDigest` (AD-SYS-2 rule 9): "Resumen del {dia}: {n} entregas fallidas (la más antigua desde {fecha}) y {m} atascadas." in `typography.meta`. Hidden when no digest exists yet or both counts are 0 |
| Columns | Event (name plus `eventId` in `typography.code`) · subscriber · status ("Fallida" / "Atascada") · attempts, as "{n} de 3" for automatic attempts · last error class (registry code only, in `typography.code`) · times, absolute plus relative age: "Fallida" rows show the first failure (`firstFailedAt`) and the latest (`lastFailedAt`); "Atascada" rows show the creation (`createdAt`) and the latest attempt (`lastAttemptAt`) |
| Row action | "Reintentar" → `admin.events.replay({ eventId, subscriber })` (ARCHITECTURE §7.3). The button shows "Reintentando…" and is disabled while the call runs |
| Success | The row leaves the list; live region "Entrega reintentada: {evento} → {suscriptor}." |
| Not replayable | `EventDeliveryNotReplayable`: banner "Esta entrega ya no está fallida ({estado}), así que no se puede reintentar. La lista se actualizó." and the list refetches |
| Note | "Cada reintento queda registrado. Reintentar dos veces no duplica el efecto." |
| Stuck rows | No "Reintentar" on "Atascada" rows: the sweeper still owns them (AD-SYS-2 rule 6). Note under the table: "Las entregas atascadas se reintentan solas hasta 3 veces; si no se confirman, pasan a fallidas y se pueden reintentar aquí." |

## Technical Notes

- Scheduled and manual runs share the lock (`FeedRunInProgress`).
- The page polls every 5 s while a run is active, and every 30 s otherwise.
- Quarantine counts come from `QuarantinedFeedRow`; nothing is ever partially applied (FR-CAT-3).
- The Entregas tab is owned by `shared-kernel`, not by catalog; it sits on 2.3 because ARCHITECTURE AD-SYS-2 and §7.3 place the event panel here. A concurrent replay of the same delivery is a no-op that returns its current status (§7.3). The "Última tarea horaria" line reads `JobRun` (shared-kernel, ARCHITECTURE §4); the silence alert is derived at read time, not stored. The tab reads `admin.events.deliveries` and `admin.events.deliveryHealth()`, and the header reads `admin.jobs.tickHealth()` (ARCHITECTURE §7.3).
