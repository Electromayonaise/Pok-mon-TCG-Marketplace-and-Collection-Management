## Overview

**Page Purpose:** Let collectors browse the whole catalog by set, era, Pokémon, colour, style, artist, kind and a name prefix. Entries appear whether or not anyone sells them (FR-CAT-1, FR-DSC-1 `view=entries`).

**Success Criteria:** The count and the grid always agree. Every card shows its availability in words. The filters live in the URL, so reload, share and back restore the exact state.

**Entry Points:** Bottom bar → Catálogo; a shared URL with filters; the "Ver el set completo" link in 2.2.

**Exit Points:** 2.2 card detail; 9.3 (add to wishlist, via the card menu).

## Page Sections

### Section: Name Search

**OBJECT ID:** `cat-browse-search`

| Property | Value |
|----------|-------|
| Component | `type="search"` input, 0–60 characters, debounced 300 ms |
| Behavior | Case- and accent-insensitive prefix match ("pika" matches "Pikachu", "équipo" matches "Equipo"). More than 60 characters are trimmed, with an inline note "Usamos los primeros 60 caracteres." |

### Section: Filter Panel

**OBJECT ID:** `cat-browse-filters`

| Property | Value |
|----------|-------|
| Component | Mobile: full-screen sheet opened by "Filtros (n)", with "Ver 12 cartas" as the apply button. Desktop: a left column of `<details>` groups |
| Dimensions | Set (grouped by era), Era, Pokémon (search within), Color/tipo, Estilo/rareza, Artista (search within), Tipo (Carta / Producto sellado) |
| Facet counts | Each value shows its count under the current filter, e.g. "Fuego (12)". A value with count 0 stays listed but is dimmed with the words "(0)"; it is not hidden |
| Limit | Maximum 20 values per dimension. On the 21st: "Puedes elegir hasta 20 valores por filtro." |

### Section: Active Filter Chips

**OBJECT ID:** `cat-browse-chips`

| Property | Value |
|----------|-------|
| Component | Removable chips. Each is a `<button>` with `aria-label="Quitar filtro Artista: Mitsuhiro Arita"` |
| Behavior | "Limpiar todo" appears when there are 2 or more chips |

### Section: Result Grid

**OBJECT ID:** `cat-browse-grid`

| Property | Value |
|----------|-------|
| Component | Catalog card tile (image, name, set · number, availability line) |
| Availability line | `hasActiveListings=true`: "Desde $9.000 · 4 a la venta". `false`: "Nadie la está vendiendo". The line never uses colour alone |
| Sort | `<select>` "Orden": Lanzamiento (default: release date desc → number asc) · Número · Nombre |
| Paging | 48 per page. Mobile: "Cargar más" appends. Desktop: numbered pagination. The page number is in the URL |

## Page States

| State | When | Appearance | Actions |
|-------|------|------------|---------|
| Loading | First load or filter change | Grid of `components.skeleton` tiles; the count reads "Buscando…" | — |
| Empty (catalog) | The catalog has 0 entries (fresh environment) | `empty-state`: "El catálogo aún no tiene cartas." | — |
| Zero results | The filters match nothing, including an unknown value in the URL | "Ninguna carta coincide con estos filtros." plus the chips | "Quitar filtros" (removes the last chip) / "Limpiar todo" |
| Error | Fetch failed | Banner "No pudimos cargar el catálogo en este momento. Ya quedó registrado; vuelve a intentarlo en unos segundos." | Reintentar |
| Success | Results | Grid plus count | Open a card, change filters |

---

## Technical Notes

- Filter state is serialised to the query string (`?set=…&artist=…&colour=…&page=2`), so Back restores it. Unknown values are kept in the chips as typed, so the person can see and remove them.
- Availability comes from the DSC composition (`view=entries`, FR-DSC-1). With no area set, it is nationwide.
- Performance budget: NFR-CAT-1 (≤ 1,000 ms p95 over 10,000 entries). The skeleton appears after 100 ms (EXPERIENCE → Interaction Primitives).
