## Overview

**Page Purpose:** Let a verified shop see paid orders, open the comprobante safely and record "Recibí el pago" as its own fact (FR-ORD-4). Explain the case where the buyer closed first (FR-ORD-5, FR-COM-4).

**Success Criteria:**
- Unpaid orders never appear (not even as a count).
- Confirming is one deliberate action next to the evidence.
- A second confirmation from another tab is explained with the original time.

**Entry Points:** Mi tienda → Pedidos; the 7.2 ledger line "Ver pedido"; a poll-driven count on the Mi tienda nav ("Pedidos · 1 por confirmar").

**Exit Points:** 7.2 (the ledger line for this order); 12.2 (the conversation with the buyer, when one exists).

## Page Sections

### Section: Order List

**OBJECT ID:** `ord-desk-list`

| Property | Value |
|----------|-------|
| Component | `data-table` with tabs: Por confirmar (Pagado) · Confirmados (Pago confirmado) · Cerrados. Columns: order (short id), buyer display name, product, total, "Pagó el" |
| Order | Por confirmar: oldest "Ya pagué" first. Others: newest first |
| Paging | 25 per page, keyset |
| Empty | Por confirmar: "No tienes pagos por confirmar." |

### Section: Order Detail

**OBJECT ID:** `ord-desk-detail`

| Property | Value |
|----------|-------|
| Facts | Three rows with the buyer's name: "{comprador} confirmó que pagó" · "Tú confirmas que recibiste el pago" · "{comprador} recibe la carta" |
| Snapshot | Product, quantity, total and the payment details as they were when the order was created (masked to the last 4 digits) with the line "Datos con los que se pidió el pago" |
| Buyer-closed | If the buyer closed before the shop confirmed: the §4 "Business sees buyer-closed order" copy, with "Ver movimiento" → 7.2 filtered to this order. No confirm button (the order is Cerrado) |

### Section: Comprobante Viewer

**OBJECT ID:** `ord-desk-comprobante`

| Property | Value |
|----------|-------|
| Component | `comprobante-viewer`: the sanitized rendition only, shown as an image, never the original file (ARCHITECTURE AD-SYS-8 rule 11; the PDF rendition is pending G-5); view only, no download. Caption "Solo lectura · enlace válido 10 min" |
| Expiry | After 600 s the frame shows "El enlace expiró." with "Volver a abrir" (a new signed URL) |
| Hint | "Revisa tu banco antes de confirmar." |

### Section: Confirm Payment

**OBJECT ID:** `ord-desk-confirm`

| Property | Value |
|----------|-------|
| Command | `button-primary` "Recibí el pago". Single step, no dialog (not destructive; the fact is what the shop asserts) |
| Success | Re-render as Pago confirmado; live region "Confirmaste el pago de Camila · {hora}"; the row moves to Confirmados; a line appears: "La comisión de este pedido se descontó de tu saldo." → "Ver movimiento" (7.2) |
| Duplicate | `OrderAlreadyConfirmedByRole` info banner with the original `{fecha}` |
| Defensive | `ComprobanteMissingOnConfirm` banner (not reachable in normal use) |

## Technical Notes

- The list query filters on `buyerPaidConfirmedAt IS NOT NULL` server-side; no unpaid order ever reaches the client (AD-15).
- The page never shows a commission amount computed on the client. The line after confirmation links to the ledger, which is the only source of the amount.
- A shop whose balance is exhausted still sees and confirms existing paid orders; the pause affects new purchases only (FR-INV-7).
