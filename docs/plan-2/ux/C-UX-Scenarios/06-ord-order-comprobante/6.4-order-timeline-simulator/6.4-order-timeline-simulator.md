## Overview

**Page Purpose:** Make the order state machine and its refusals observable and repeatable. A developer drives one order through any sequence of commands as any actor, runs the mandatory edge sequences ×100, and moves the virtual clock to test expiry and the 7-day stall.

**Success Criteria:**
- Every command shows its `Decision` (outcome, reasonCode, es-CO message, citations) before the JSON.
- The race presets report a per-run tally and highlight any run that breaks an invariant.
- The 3 unreachable fact combinations are shown as unreachable, with the command that proves it.

**Entry Points:** `/dev` index → "Pedidos"; links from 4.3 ("Ver en el simulador de pedidos").

**Exit Points:** 6.2 / 6.3 (open the fixture order in the product surface as the selected actor).

## Page Sections

### Section: Console Header

**OBJECT ID:** `ord-sim-header`

| Property | Value |
|----------|-------|
| Actor switcher | Camila (buyer), Andrés (business), Valentina (unrelated), Sebastián (admin), anonymous |
| Virtual clock | "+1 h / +48 h / +7 d / fecha exacta"; the fixture order is created at 12 oct 2026, 4:20 p. m. with `expiresAt` 14 oct 2026, 4:20 p. m. |
| Sweep | "Barrer ahora" runs the FR-ORD-8 sweep once at the virtual time and reports "{n} vencidos · {m} reservas liberadas" |

### Section: State Machine

**OBJECT ID:** `ord-sim-states`

| Property | Value |
|----------|-------|
| Component | `state-machine-viewer`: the 6 derived statuses from addendum §4.2 as nodes, the current one highlighted with an outline and the word "actual" |
| Facts | The three fact timestamps under the graph, each with its time or "—" |
| Unreachable | A list of the 3 unreachable combinations. Each links to the preset that attempts it and shows the refusing code (`OrderNotVisibleToCaller` or `OrderConfirmationOutOfOrder`) |

### Section: Command Runner

**OBJECT ID:** `ord-sim-commands`

| Property | Value |
|----------|-------|
| Commands | Comprar (listing select, qty), Subir comprobante (fixture select: JPEG válido · PDF válido · 6 MB · .exe renombrado), Ya pagué, Recibí el pago, Ya recibí la carta, Cancelar |
| Output | `api-explorer-panel`: the Decision banner first (es-CO message as the user would read it), then the JSON, then the state view refresh |
| Forced reserve | A listings-stub toggle "Forzar resultado de reserva": normal · `NotBusinessListing` · `InsufficientQuantity` · `ListingNotPurchasable`. With `NotBusinessListing`, the output also shows "Cantidad antes {n} · después {n} · pedidos creados 0 · filas de reserva 0" |

### Section: Race Presets

**OBJECT ID:** `ord-sim-races`

| Property | Value |
|----------|-------|
| Component | `race-simulator` with the NFR-ORD-1 presets: "Negocio antes del pago", "Negocio sin comprobante", "Doble clic en cada confirmación", "Dos pestañas por rol", "Pagado vs vencimiento en expiresAt", "Compra forzada a publicación individual" |
| Run | 100 repetitions by default |
| Tally | Per preset: counts per outcome plus invariant checks: "cada hecho a lo sumo una vez ✓", "cada rechazo con código ✓", "eventos por pedido ≤ 1 ✓", "orden de hechos ✓". Paid vs expiry adds "ambos 0 ✓" and "reserva liberada una vez ✓" |
| Failure | Any broken invariant marks the run "FALLA", with a link to its trace |

## Technical Notes

- The console calls the same tRPC procedures as the product surfaces, with the actor's test session; it has no private back door.
- The virtual clock affects only this console's fixture tenant; the sweep uses it as `now`.
- Refusals are shown as normal outcomes (neutral colour), not as console errors; only runner failures are errors.
