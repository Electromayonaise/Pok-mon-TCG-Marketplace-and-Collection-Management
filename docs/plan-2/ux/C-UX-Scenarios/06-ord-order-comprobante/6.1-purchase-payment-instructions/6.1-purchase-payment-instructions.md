## Overview

**Page Purpose:** Turn "Comprar" into an order with the unit already reserved (FR-ORD-1). Then show, on one screen, who to pay, how much, with which details and by when. Every refusal says why and gives a next step; none of them creates an order.

**Success Criteria:**
- The confirm step shows the exact total before the buyer commits.
- After creation, the payment details and the absolute pay-by time are visible without scrolling on a 360 × 640 screen.
- A refusal never leaves a half-created order or a held unit.

**Entry Points:**
- 2.2 listings block → "Comprar" on a business row that can be bought;
- 3.1 row → "Comprar";
- a deep link or stale page for any listing (it may end in a refusal).

**Exit Points:**
- 6.2 ("Ir al pedido");
- 2.2 ("Buscar otra publicación de esta carta");
- 6.2 of an existing order (the `TooManyOpenOrders` actions);
- 12.1 (`NotBusinessListing`);
- 4.2 (`SelfPurchaseNotAllowed`).

## Page Sections

### Section: Confirm Step

**OBJECT ID:** `ord-buy-confirm`

| Property | Value |
|----------|-------|
| Summary | `listing-card` compact: item title, condition, shop name with the verified badge, and distance if known |
| Quantity | Stepper from 1 to the available quantity. It is hidden when only 1 unit is available (the text "1 disponible" shows instead) |
| Total | `price-block`: unit price × quantity = total. Integer COP, recomputed on every quantity change |
| Bundle | Shows "Incluye:" with the component list (title · condition · ×n) |
| Settlement line | "Pagarás directamente a la tienda. TEZG no recibe tu dinero." |
| Reservation line | "La carta queda apartada para ti apenas confirmes." |
| Action | `button-primary` "Confirmar compra". It carries the listing's current version; the server is the arbiter |

### Section: Refusal Banner

**OBJECT ID:** `ord-buy-refusal`

| Property | Value |
|----------|-------|
| Placement | Replaces the "Confirmar compra" area (first-fail). The summary stays visible |
| `TooManyOpenOrders` (per business) | §4 copy with `{tienda}` → "Ver pedido" (that order's 6.2) |
| `TooManyOpenOrders` (total) | §4 copy → "Ver pedidos sin pagar" (Actividad → Pedidos filtered to Por pagar) |
| `SelfPurchaseNotAllowed` | §4 copy → "Ver mis publicaciones" (4.2) |
| `NotBusinessListing` | §4 copy with `{nombre}` → "Contactar al vendedor" (12.1) |
| `ListingNotPurchasable` | §3 copy for the cited reason (unverified, paused, withdrawn, deactivated) → "Buscar otra publicación de esta carta" |
| `InsufficientQuantity` | Last unit: "Otra persona reservó la última unidad hace un momento. Esta publicación ya no tiene unidades disponibles." Partial: "Solo quedan {n} disponibles." The stepper resets to the new maximum, and the button returns |
| `ListingNotFound` | Not-available page |
| `EmailNotVerified` | IDN copy → "Verificar mi correo" |

### Section: Payment Instructions (result)

**OBJECT ID:** `ord-buy-instructions`

| Property | Value |
|----------|-------|
| Headline | `state-indicator` "Por pagar" plus the §4 Created copy with `{tienda}` and `{fecha}` = `expiresAt` in Bogotá time |
| Block | `payment-details-block` from the order's **snapshot**: total to transfer, bank, account type, account number, holder, optional QR. Each value has "Copiar"; a copy is confirmed in the live region ("Número de cuenta copiado") |
| Snapshot note | "Estos datos quedaron guardados con tu pedido." |
| Action | `button-primary` "Ir al pedido" → 6.2 |
| Secondary | Text link "Cancelar pedido" → 6.2 with the cancel dialog open (destructive, FR-ORD-7) |

## Page States

| State | When | Appearance | Actions |
|-------|------|------------|---------|
| Loading | Listing fetch | `skeleton` summary | — |
| Empty | Not applicable | The page always renders one listing, or a refusal when the listing no longer resolves | — |
| Submitting | "Confirmar compra" sent | The button shows "Apartando la carta…"; at 10 s "Sigue en proceso…" | — |
| Error — refusal | Domain code | `ord-buy-refusal` | Per the banner |
| Error — transport | Create not confirmed | §10 "No sabemos si…" copy. "Ver mis pedidos" shows whether the order exists; there is no automatic retry | Ver mis pedidos |
| Success | Order created | The page re-renders as `ord-buy-instructions`; the live region announces "Pedido creado. Paga antes del {fecha}."; the URL becomes `/pedidos/<orderId>/pago` | Ir al pedido |
| Revisit | Buyer returns to `/pedidos/<id>/pago` later | Same result view, from the snapshot. If the order is no longer Por pagar, redirect to 6.2 | — |

---

## Technical Notes

- A single `orders.purchase` command runs the open-order count, the reserve and the insert in one transaction (FR-ORD-1). The UI never pre-checks quantity to hide the button; availability shown on 2.2 is informational only.
- The payment details come only from the order snapshot. A later edit on 5.2 never changes them (FR-VER-9).
- Back navigation from the result does not resubmit, because the confirm step's URL renders the listing afresh.
