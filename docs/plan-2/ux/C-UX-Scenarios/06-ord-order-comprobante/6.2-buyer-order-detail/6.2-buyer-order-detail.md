## Overview

**Page Purpose:** The buyer's single place for one order. It shows the three facts individually with times (FR-ORD-6), takes the comprobante and "Ya pagué" (FR-ORD-2, FR-ORD-3), closes the order with "Ya recibí la carta" (FR-ORD-5) and cancels before payment (FR-ORD-7). It explains expiry and stalls in words (FR-ORD-8, NFR-ORD-4).

**Success Criteria:**
- At every moment exactly one next action is primary, and it belongs to the buyer; otherwise the page says whose turn it is, by name.
- "Pagado" never appears before the upload and the confirmation both exist.
- Closing shows the collection prompt in place; the order never adds to a collection by itself.

**Entry Points:** 6.1 "Ir al pedido"; Actividad → Pedidos; the `TooManyOpenOrders` actions on 6.1; the post-close notice.

**Exit Points:**
- 9.4 (the inline prompt; the full list opens from "Ver sugerencias");
- 11.1 ("Ahora puedes reseñar a {tienda}");
- 12.2 ("Escribir a la tienda") or the support contact (expired and stalled states).

## Page Sections

### Section: Header and Status

**OBJECT ID:** `ord-detail-header`

| Property | Value |
|----------|-------|
| Content | Snapshot title, condition and total; shop name with the badge as snapshotted; bundle components listed under "Incluye:" |
| Status | Derived label (Por pagar · Pagado · Pago confirmado · Cerrado · Cancelado · Vencido) with a `state-indicator` glyph; never colour alone |

### Section: Facts List

**OBJECT ID:** `ord-detail-facts`

| Property | Value |
|----------|-------|
| Component | `order-status-row` expanded as an ordered list of three rows: "Pagaste" · "{tienda} confirmó que recibió tu pago" · "Recibiste la carta". Each row is filled with its time, or hollow with "pendiente" |
| Before payment | The list is replaced by the §4 Created copy with the pay-by `{fecha}`, so that an unpaid order is never read as three unset dots (Plan-1 carry-over) |
| Closed without the shop's confirmation | The second row reads "{tienda} no confirmó el pago antes de que cerraras el pedido". This is a fact, not an error |

### Section: Comprobante and "Ya pagué"

**OBJECT ID:** `ord-detail-pay`

| Property | Value |
|----------|-------|
| Shown when | Por pagar |
| Upload | `upload-dropzone`, one file, JPEG/PNG/PDF, ≤5 MB. The server validates the content signature. Errors use the `ComprobanteInvalidFile` type or size copy with `{peso}` to one decimal. A refused file leaves the previous accepted file (if any) in place |
| Replace | "Cambiar archivo" while Por pagar |
| Command | `button-primary` "Ya pagué". With no accepted file, the button still shows; pressing it returns `ComprobanteNotYetUploaded`, shown as a banner with "Subir comprobante", which focuses the dropzone |
| After success | The page re-renders as Pagado; the live region says "Confirmaste tu pago · {hora}"; the dropzone becomes a read-only file row with the `ComprobanteLocked` explanation on hover/focus of "Cambiar archivo" (disabled with visible text, not hidden) |
| Payment details | A collapsible `payment-details-block` from the order snapshot, open by default while Por pagar |

### Section: "Ya recibí la carta"

**OBJECT ID:** `ord-detail-received`

| Property | Value |
|----------|-------|
| Shown when | Pagado or Pago confirmado |
| Command | `button-primary` "Ya recibí la carta". It is a single-step command, not a dialog (EXPERIENCE: no modal for non-destructive steps). Helper text: "Hazlo cuando tengas la carta en la mano." |
| Out of order | If the order is not yet paid (e.g. a stale tab), the reply is `OrderConfirmationOutOfOrder`, shown as a banner with the action "Ya pagué" |
| After success | The page re-renders as Cerrado; the live region says "Pedido cerrado · {hora}"; the prompt card appears below the facts |

### Section: Collection Prompt and Review Link

**OBJECT ID:** `ord-detail-after-close`

| Property | Value |
|----------|-------|
| Prompt | `prompt-card` (owned by COL 9.4): "¿Agregar {producto} a tu colección?" with a collection select (default: the most recently used), "Agregar" and "Ahora no". Bundles list one line per component. It is shown only while the prompt is Pending |
| Review link | "Ahora puedes reseñar a {tienda}" → 11.1. Shown when `hasClosedPurchase` is true and the buyer has not reviewed this shop yet; otherwise "Ver tu reseña" |

### Section: Cancel

**OBJECT ID:** `ord-detail-cancel`

| Property | Value |
|----------|-------|
| Shown when | Por pagar |
| Trigger | `button-secondary` "Cancelar pedido" |
| Dialog | `<dialog>`: "Cancelar el pedido de {producto} a {tienda}. La carta vuelve a estar disponible para otros compradores. Si ya transferiste, no canceles: sube tu comprobante." Buttons "Volver" · `button-destructive` "Cancelar pedido" |
| After success | Re-render as Cancelado with the §4 cancelled copy; live region "Pedido cancelado" |
| Refused | `OrderNotCancellable` with the cause in words (the page re-fetches) |

### Section: Terminal and Stalled Notices

**OBJECT ID:** `ord-detail-notices`

| Property | Value |
|----------|-------|
| Expired | `OrderNoLongerActive` (expired) copy with `{fecha}` and `{tienda}`. The snapshot payment details stay visible so the buyer can prove a transfer; action "Escribir a la tienda" → 12.2 |
| Cancelled | §4 cancelled copy |
| Stalled (≥7 days in Pagado) | Stalled copy (NFR-ORD-4) with "Escribir a la tienda" and "Contactar a soporte". The support contact comes from configuration (FR-ORD-10). No deadline is shown, because none exists (FR-ORD-8) |
| Waiting (<7 days in Pagado) | "Esperando a que {tienda} confirme el pago." with no action |

## Page States

| State | When | Appearance | Actions |
|-------|------|------------|---------|
| Loading | Fetch | `skeleton` header and fact rows | — |
| Empty | — | Not applicable (a record page). The list page has "Aún no tienes pedidos." | — |
| Error — domain | A command refused | Inline banner above the command, per §4 | Per the banner |
| Error — lost race | The expiry sweep won against "Ya pagué" | Re-fetch; the expired notice replaces the upload; banner "Este pedido venció el {fecha} antes de que confirmaras el pago." | Escribir a la tienda |
| Error — duplicate | `OrderAlreadyConfirmedByRole` | Info banner with the original `{fecha}`; nothing changes | — |
| Error — transport | Command not confirmed | §10 copy; "Actualizar" re-reads the true facts | Actualizar |
| Error — not visible | Not the buyer | Not-available page "No encontramos este pedido en tu cuenta." | Ver mis pedidos |
| Success | Each command | Re-render plus a polite live-region line; no toast | — |
| Changed while open | The shop confirmed (poll every 30 s, refetch on focus) | Live region: "Tienda Andrés confirmó que recibió tu pago · {hora}"; the fact row fills | — |

## Technical Notes

- Every command sends the order id only; the server derives the actor. Buttons are never pre-disabled from a stale poll; the server answers with an explained code (NFR-ORD-1).
- The comprobante "Ver" opens the `comprobante-viewer` with a fresh 600 s signed URL each time. It renders only the sanitized rendition (ARCHITECTURE AD-SYS-8 rule 11; the PDF rendition is pending G-5). On expiry the frame shows "El enlace expiró." with "Volver a abrir".
- The 7-day stalled state is computed from `buyerPaidConfirmedAt` against server time, and it is exercised with the 6.4 virtual clock.
