## Overview

**Page Purpose:** Show every trade the person is part of, as proposer or as seller, sorted so that what needs them comes first. Every ended row says in words why it ended, so no offer ever silently disappears, including those that became unfulfillable because the seller accepted another offer on the same or a sibling listing.

**Success Criteria:**
- Rows that need the caller ("Te toca responder", an accepted trade waiting on the caller's confirmation) are on top and counted on the Actividad tab.
- Every non-open row carries its status line from §6, including the reason for "No disponible".
- A proposer can go from an unfulfillable row to other listings of the same card in one tap.

**Entry Points:** Actividad tab "Intercambios" (with the pending count); 8.2 back link.

**Exit Points:** 8.2 (any row); 2.2 ("Buscar otra publicación de esta carta"); 2.1 (empty state).

## Page Sections

### Section: Filters

**OBJECT ID:** `trd-list-filters`

| Property | Value |
|----------|-------|
| Chips | Pendientes (Open) · Aceptados (Accepted, not completed) · Completados · Terminados (Rejected, Withdrawn, Expired, Unfulfillable, Cancelled). Default: the first non-empty chip in this order (Pendientes, Aceptados, Completados, Terminados). There is no "Todos" chip |
| Counts | Each chip shows its count; chips at 0 are shown but not selected by default |
| Role | A secondary toggle "Todas · Las que hice · Las que recibí" |

### Section: Trade List

**OBJECT ID:** `trd-list-rows`

| Property | Value |
|----------|-------|
| Component | `trade-offer-card` compact row, whole row is the link to 8.2 |
| Order | Rows needing the caller first (their turn; accepted and waiting on them), then by last activity, newest first; ties broken by offer id (cuid2) so the order is stable |
| Row content | Status word + `state-indicator` · listing title (bundle: "Lote Psíquico") · "con {nombre}" · one context line: round and absolute expiry (Open), who is being waited on (Accepted), or the §6 end line with its date (ended) |
| Unfulfillable, proposer | "No disponible" + the `ListingNoLongerAvailable` line + link "Buscar otra publicación de esta carta" (→ 2.2 of the listing's card, or of the first bundle component that ran out). The row is inert tone, not error: nothing the proposer did was wrong |
| Unfulfillable, seller | "Sin efecto" + the §6 seller line "Esta oferta quedó sin efecto porque aceptaste otra por la misma carta el {fecha}." (identical to 8.2) |
| Expired | "Vencida" + "Esta oferta venció el {fecha} sin respuesta." + "Hacer una nueva oferta" (proposer only) |
| Cancelled | "Cancelado" + "{nombre / Tú} canceló el intercambio el {fecha}." |
| Paging | 20 rows, "Ver más" appends the next 20 |

### Section: Tab Count

**OBJECT ID:** `trd-list-count`

| Property | Value |
|----------|-------|
| Value | Number of offers where it is the caller's turn plus accepted trades waiting on the caller's confirmation |
| Placement | On the Actividad "Intercambios" tab, as number + dot per `message-thread.unread-count` styling |
| Freshness | Recomputed when the Actividad shell refetches (on focus, and every 30 s while 8.2 or 8.3 is visible) |

## Technical Notes

- The list reads the same visibility rule as 8.2: the query is scoped by `proposerId = me OR sellerId = me`; there is no admin view of offers (FR-TRD-3, aggregate counts only).
- Unfulfillable rows produced by FR-TRD-5 appear in the same query as any other ended offer; the reason comes from the round history, so the row text is identical to the 8.2 banner.
- "Completado" is read from the computed `completed` field.
