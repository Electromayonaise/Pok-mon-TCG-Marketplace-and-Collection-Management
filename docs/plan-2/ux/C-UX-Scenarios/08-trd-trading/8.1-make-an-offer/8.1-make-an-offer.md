## Overview

**Page Purpose:** Let a collector put together a complete, structured trade offer on one individual-seller listing that is open to trades: up to 10 catalog items (each with a condition and a quantity), cash, and a short note. The page states plainly that the offer reserves nothing and when it will expire.

**Success Criteria:**
- The offer is sent in one screen. The summary line is what the seller will read.
- Every refusal from FR-TRD-1 appears in place, with its reason and next step, and with no disabled "Enviar oferta" left unexplained.
- The expiry is shown as an absolute date before sending ("Si {nombre} no responde, la oferta vence el {fecha}").

**Entry Points:** 2.2 listings block, "Hacer una oferta" on an individual open-to-trade row; 8.2 "Hacer una nueva oferta" (after rejection or expiry, prefilled with the last terms).

**Exit Points:** 8.2 (offer created); 2.2 ("Volver a la carta"); 8.2 of the existing offer ("Ver mi oferta", on `DuplicateOpenOffer`).

## Page Sections

### Section: Requested Listing

**OBJECT ID:** `trd-offer-requested`

| Property | Value |
|----------|-------|
| Component | `listing-card` (compact), read-only |
| Content | Listing title; for a bundle, its component cards with conditions; seller display name; "1 disponible"; the listing's price ("Precio publicado $95.000"), labelled so it is never confused with the CAT reference price |
| Quantity | Always 1 (`requestedQty: 1`); no quantity control |
| Pre-check | On load the page calls `getTradeability`; if it refuses, the refusal banner replaces the Ofreces block (see Page States), so the collector does not fill a form that cannot be sent |

### Section: Offered Items

**OBJECT ID:** `trd-offer-items`

| Property | Value |
|----------|-------|
| Search | Catalog search (name or set number) → result list with image, set and number. Choosing a result adds a row |
| Shortcut | "Tus cartas" lists the proposer's inventory units as quick picks. It is a convenience only: items are catalog references (`itemRef`) validated by `listings.resolveItemRefs`, and ownership is not checked |
| Row | Name · condition select (NM, LP, MP, HP, DMG) · quantity stepper 1–4 · "Quitar" |
| Limit | 10 rows; the add control shows "(n de 10)" and is replaced by the §6 item-limit line at 10 |
| Errors | An unresolvable reference (the catalog entry was merged or removed while the form was open) shows `field-error` on that row with the §3/§6 copy and keeps the other rows |

### Section: Cash and Note

**OBJECT ID:** `trd-offer-cash-note`

| Property | Value |
|----------|-------|
| Cash | Integer COP field, 0–10.000.000, formatted "$20.000" on blur; `inputmode="numeric"`. Out of range → `field-error` "El efectivo debe estar entre $0 y $10.000.000." |
| Note | Textarea, 0–300 characters, counter "n/300" in `typography.meta`; the label names the seller ("Nota para Valentina (opcional)") |
| Guidance | No contact details are requested here. Contact is exchanged only after acceptance (FR-TRD-6) |

### Section: Summary and Send

**OBJECT ID:** `trd-offer-summary`

| Property | Value |
|----------|-------|
| Summary | §6 offer summary, recomputed on every change, following the `{items} + {efectivo}` composition rule |
| Non-binding line | "La oferta no reserva la carta. Si {nombre} no responde, vence el {fecha}." The date is now + 7 days on the virtual clock, absolute (never a countdown) |
| Action | "Enviar oferta" (`button-primary`). Always enabled; an empty offer is refused by the server with `EmptyTradeOffer`, shown as a `field-error` above the button and focused |
| Success | Navigates to 8.2 of the new offer; its live region announces the §6 "Oferta enviada…" line |
| Double submit | The button shows "Enviando…" and ignores further activations until the response arrives. A retry after a network loss gets `DuplicateOpenOffer` if the first send succeeded, which leads to "Ver mi oferta" |

## Page States

| State | When | Appearance | Actions |
|-------|------|------------|---------|
| Loading | Listing and tradeability loading | `skeleton` listing card and form | — |
| Default | Tradeable listing | As in the layout, empty Ofreces block | Buscar, Tus cartas, Enviar oferta |
| Filled | Items or cash added | Summary line updated | Enviar oferta |
| Refused on load — not open | `ListingNotOpenToTrade` | `explainability-banner` refusal: "Valentina no abrió esta carta a intercambios. Puedes escribirle para comprarla." | Contactar al vendedor |
| Refused on load — shop | `NotIndividualSellerListing` | Refusal banner with the §3 copy | Comprar |
| Refused on load — own listing | `SelfTradeNotAllowed` | Refusal banner with the §6 copy | Ver mis publicaciones |
| Refused on load — no units | `InsufficientQuantity` | Refusal banner with the §3 copy | Buscar otra publicación de esta carta |
| Refused on load — duplicate | `DuplicateOpenOffer` | Refusal banner with the §6 copy | Ver mi oferta |
| Refused — email | `EmailNotVerified` | Refusal banner with the §1 copy | Reenviar enlace |
| Refused on send | Any of the above arriving on send (state changed in between) | Same banner at the top, form kept so nothing typed is lost | As above |
| Error — network | Request failed | Banner with the §10 "command not confirmed" copy ({acción} = "tu oferta"): "No sabemos si tu oferta se guardó porque se perdió la conexión. Actualiza para ver el estado actual; si no se guardó, puedes repetirla sin riesgo." | Actualizar |

## Technical Notes

- The load-time pre-check and the send use the same `getTradeability` rules in the same order as FR-TRD-1 (first failure wins), so the page never shows two refusals at once.
- The form state is kept in the URL-independent draft store for the session, so a refusal banner never clears what the collector typed.
- The expiry preview uses the server's clock (the virtual clock in fixtures), returned with the tradeability check, not the device clock.
- No reservation or inventory call is made at offer time (FR-TRD-1, non-binding).
