## Overview

**Page Purpose:** One place where both parties see the whole negotiation (every round, with what changed), know at a glance whose turn it is, act only when it is theirs, and then carry an accepted trade through the off-platform meeting to a mutual "Completado". Everything the other party does arrives within 35 s without a reload.

**Success Criteria:**
- The current terms and whose turn it is are visible without scrolling on a 360 px screen.
- The page offers only the actions the caller can take in the current status and turn; a stale tab that acts anyway gets a named, explained refusal and re-renders to the current state.
- After acceptance, both parties can start the conversation in one tap (proposer) or one copy (seller).
- "Completado" appears only when both have confirmed, and it is computed, never stored.

**Entry Points:** 8.1 (new offer); 8.3 rows; the Actividad → Intercambios pending count; a shared deep link.

**Exit Points:** 8.1 ("Hacer una nueva oferta"); 2.2 ("Buscar otra publicación de esta carta"); WhatsApp or the copied text (the handoff); 8.3.

## Page Sections

### Section: Header

**OBJECT ID:** `trd-neg-header`

| Property | Value |
|----------|-------|
| Title | "Intercambio con {nombre de la otra parte}" |
| Listing line | Listing title, card count for bundles, "Precio publicado {precio}"; links to the listing |
| Back | "Mis intercambios" → 8.3 |

### Section: Status and Turn

**OBJECT ID:** `trd-neg-status`

| Property | Value |
|----------|-------|
| Component | `state-indicator` + one line; for ended states an `explainability-banner` |
| Open, caller's turn | pending · "Te toca responder" · "Vence el {fecha}" |
| Open, other's turn | pending · "Le toca a {nombre}" · "Vence el {fecha}" |
| Accepted | confirmed · §6 Accepted copy ("…reservada para ti." to the proposer, "…reservada para {nombre}." to the seller) |
| One confirmation | pending · "Confirmaste el {fecha} · Esperando a que {nombre} confirme." or "{nombre} confirmó que el intercambio se hizo." |
| Completed | confirmed · "Completado: ambos confirmaron el intercambio el {fecha}." (date of the second confirmation) |
| Rejected | error · "{nombre / Tú} rechazó la oferta el {fecha}." |
| Withdrawn / Expired / Cancelled | inert · the §6 line for each |
| Unfulfillable (proposer) | inert banner · "{nombre} aceptó otra oferta por esta carta, así que esta no puede continuar." → "Buscar otra publicación de esta carta" |
| Unfulfillable (seller) | inert · "Esta oferta quedó sin efecto porque aceptaste otra por la misma carta el {fecha}." |

### Section: Current Terms

**OBJECT ID:** `trd-neg-terms`

| Property | Value |
|----------|-------|
| Component | `trade-offer-card` |
| Content | "{proponente} da:" item list (name, condition, ×qty when > 1) · "Efectivo:" amount or "sin efectivo" · "{vendedor} da:" the listing (quantity 1) |
| Change marker | Each line that differs from the previous round carries "cambió" in `typography.meta`. The marker is text, never colour alone |
| Long lists | More than 3 items collapse to "+{n} cartas más", expandable in place |

### Section: Actions

**OBJECT ID:** `trd-neg-actions`

| Status / caller | Actions shown |
|-----------------|---------------|
| Open · caller's turn · round < 10 | "Aceptar" (`button-primary`) · "Contraofertar" (`button-secondary`, opens the terms editor inline) · "Rechazar" (`button-destructive`, `<dialog>`: "¿Rechazar la oferta? {nombre} no podrá retomarla; tendrá que hacer una nueva.") |
| Open · caller's turn · round = 10 | "Aceptar" · "Rechazar", plus the §6 round-limit line where "Contraofertar" was |
| Open · proposer (either turn) | "Retirar oferta" (text button, `<dialog>` with the §6 withdraw copy) |
| Open · other's turn · seller | No actions; the turn line only |
| Accepted · neither confirmed | "Ya hicimos el intercambio" (`button-primary`, no dialog: it states a fact and a repeat is refused harmlessly) · "Cancelar intercambio" (text button, `<dialog>` with the §6 cancel copy) |
| Accepted · caller confirmed | None; the waiting line |
| Accepted · only the other confirmed | "Ya hicimos el intercambio" only; cancel is gone (FR-TRD-8) |
| Ended states | Proposer: "Hacer una nueva oferta" (→ 8.1 prefilled) where §6 offers it; seller: none |
| Accept feedback | Live region: the §6 Accepted line. Accept is not behind a dialog: it is the caller's own decision on the terms shown, and the terms on screen are the version the conditional update checks |

### Section: Counter Editor

**OBJECT ID:** `trd-neg-counter`

| Property | Value |
|----------|-------|
| Behaviour | Opens inline under the current terms, prefilled with them. Reuses 8.1's `trd-offer-items` and `trd-offer-cash-note` (same limits and field errors). Only the offered side (items + cash) and a new note can change; the listing and quantity are fixed |
| Send | "Enviar contraoferta" → new round appended at the top of the history, turn passes; live region "Contraoferta enviada. Le toca responder a {nombre}." |
| Cancel | "Descartar cambios" closes the editor with no request |
| Unchanged terms | A counter identical to the current terms is caught before any request: an inline `field-error` "No cambiaste nada. Si estos términos te sirven, usa «Aceptar»." and focus on the items list. [ASSUMPTION: the PRD does not refuse an identical counter server-side. Phase 3 decides whether FR-TRD-2 adds that rule; see `review-ux-edge-cases.md`.] |
| Other party acts while open | If a poll finds the offer no longer Open (withdrawn, expired or unfulfillable), the editor closes. The draft is discarded because it no longer applies (UX-D-7), and the §6 ended banner takes its place, announced in the live region. While the offer stays Open, the draft is kept across polls. |

### Section: Contact Handoff

**OBJECT ID:** `trd-neg-handoff`

| Property | Value |
|----------|-------|
| Shown when | Status Accepted (with or without confirmations) |
| Proposer | `contact-composer` with the §7 trade handoff text generated by `listings.generateContactMessage` (FR-TRD-6), "Abrir WhatsApp" (the seller's external-contact link) and "Copiar mensaje" ("Copiado" in the live region) |
| Seller | A read-only frame with the §6 seller handoff summary and the proposer's display name, plus "Copiar resumen". No external link is shown to the seller |
| Rendering | The page shows the text the listings service returned; it never composes it client-side |

### Section: History

**OBJECT ID:** `trd-neg-history`

| Property | Value |
|----------|-------|
| Component | `trade-timeline` |
| Order | Newest round first |
| Row | "Ronda {n} · {nombre} · {fecha}" then the §6 round line (offer / counter) and the note if any. System entries (accepted, rejected, withdrawn, expired, unfulfillable with its reason, cancelled, each confirmation) appear as rounds without terms |
| Names | Always the person's name; "Tú" for the caller |

## Page States

| State | When | Appearance | Actions |
|-------|------|------------|---------|
| Loading | First load | `skeleton` status block, terms card and 2 history rows | — |
| Empty | Not applicable | An offer always has at least one round, so the history is never empty | — |
| Open — your turn | `status=Open`, `turn` = caller | As in the layout | Aceptar, Contraofertar, Rechazar (+ Retirar oferta for the proposer) |
| Open — their turn | `turn` = other | "Le toca a {nombre}" | Proposer: Retirar oferta |
| Accepted | Just accepted or reopened later | Accepted banner + handoff | Ya hicimos el intercambio, Cancelar intercambio |
| Waiting | One confirmation | Waiting line | Depends on who confirmed |
| Completed | Both confirmed | Completed banner; handoff kept for reference | — |
| Ended | Rejected / Withdrawn / Expired / Unfulfillable / Cancelled | Banner per §6 | Hacer una nueva oferta or Buscar otra publicación de esta carta (proposer) |
| Refused — not your turn | Stale tab acts out of turn | Refusal banner "Le toca responder a {nombre}. Te avisaremos aquí cuando lo haga."; page re-fetched | — |
| Refused — not open | Stale tab acts on an ended offer | Generic `TradeOfferNotOpen` copy with state and date; for a seller who accepted another offer in a second tab, the two-tabs copy with "Ver intercambio aceptado" | As in §6 |
| Refused — accept-time checks | `ListingNotOpenToTrade` or `InsufficientQuantity` on accept | Refusal banner with the §3 copy; the offer stays as the server left it (Open, or Unfulfillable after the follow-up transaction) and the page re-fetches | Retirar oferta / Buscar otra publicación de esta carta |
| Refused — already confirmed / not cancellable | `TradeAlreadyConfirmedByRole`, `TradeNotCancellable`, `TradeNotAccepted` | Refusal banner with the §6 copy; page re-fetched | — |
| Not available | `TradeOfferNotVisibleToCaller` | Not-available page: "No encontramos esta oferta en tu cuenta." | Ver mis intercambios |
| Error — network | Load or command did not complete | §10 load copy ("…cargar este intercambio…") or the command-not-confirmed copy | Reintentar / Actualizar |

## Technical Notes

- **Polling:** every 30 s while visible, paused when hidden, immediate refetch on focus (EXPERIENCE Freshness). A change from the other party is announced politely in the live region with the §6 status line it produced (for example the Accepted line when Julián accepts the counter).
- **Conditional commands:** every command sends the `version` the page rendered. A mismatch returns `NotYourTurn` or `TradeOfferNotOpen`; the page never retries a command automatically.
- **Performance budget:** accept ≤ 800 ms p95, other actions ≤ 500 ms p95 (NFR-TRD-2). The button shows a busy state after 300 ms.
- **Computed completion:** the page reads `completed` from the query result; there is no client-side inference from the two timestamps.
- **No chat here:** coordination happens through the handoff; TEZG messaging is buyer ↔ business only.
