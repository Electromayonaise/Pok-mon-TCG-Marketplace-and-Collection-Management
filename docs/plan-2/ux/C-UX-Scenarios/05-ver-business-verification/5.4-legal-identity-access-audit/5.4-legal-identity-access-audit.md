## Overview

**Page Purpose:** Prove who read which legal-identity fields, and who was refused, with 100 % coverage (FR-VER-5, NFR-VER-2).

**Success Criteria:**
- Every read and every denial appears as one row.
- The log itself never displays legal values (only field names).
- Filters answer "who saw this shop's NIT?" in one step.

**Entry Points:** Admin rail → Auditoría → "Accesos a datos legales"; "Ver accesos" on 5.3 (pre-filtered by application).

**Exit Points:** A row's application link → 5.3 detail (which is itself a new read, and says so).

## Page Sections

### Section: Filters

**OBJECT ID:** `ver-audit-filters`

| Property | Value |
|----------|-------|
| Filters | Application (search by shop name); type (Lectura · Denegado · Todos); admin or actor; date range (Bogotá). Filter state lives in the URL |

### Section: Access Log

**OBJECT ID:** `ver-audit-table`

| Property | Value |
|----------|-------|
| Columns | Tipo (`state-indicator`: filled dot and the word "Lectura" · hollow dot and the word "Denegado"); Quién (a display name; for a denial, the role reason in words: "sin permisos de administrador"); Campos (field names in Spanish: número, tipo, documento {n}); Vía (procedure name, denials only); Fecha (`{fecha}`) |
| Order | Newest first; stable tie-break by row id |
| Paging | 50 per page, keyset |
| Export | None (the audit contains personal identifiers of the actors; not required) |
| Empty | "No hay accesos registrados con estos filtros." |

### Section: Access Prober (non-production only)

**OBJECT ID:** `ver-audit-prober`

| Property | Value |
|----------|-------|
| Banner | "Consola de desarrollo · datos de prueba" |
| Action | "Probar accesos" runs the denial matrix against the selected fixture application: non-admin session → review procedure; admin → the public business-profile query; each other module's query that touches the business |
| Output | One line per attempt: the caller, procedure, outcome (`LegalIdentityAccessDenied` or "sin campos legales en la respuesta") and "fila de auditoría ✓" when exactly one denial row was written. A mismatch is highlighted "FALLA" |

## Technical Notes

- Rows are append-only. The UI has no edit or delete affordance, and the API exposes none.
- A denied attempt writes its row even when the caller's session is invalid (the actor is shown as "sesión no válida").
