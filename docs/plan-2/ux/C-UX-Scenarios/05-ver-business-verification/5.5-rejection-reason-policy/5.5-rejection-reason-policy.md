## Overview

**Page Purpose:** Maintain rejection reasons (text shown to applicants, and cooldown policy) without ever deleting one. Make clear that edits apply only to future rejections (FR-VER-8, FR-VER-4 snapshot).

**Success Criteria:**
- Every change writes one history row with before and after.
- At least one reason is always active.
- The admin can't misread an edit as retroactive.

**Entry Points:** Admin rail → Políticas → "Motivos de rechazo"; "Gestionar motivos" in the 5.3 reject dialog.

**Exit Points:** None (a leaf page).

## Page Sections

### Section: Retroactivity Notice

| Property | Value |

### Section: Reasons Table

**OBJECT ID:** `ver-policy-table`

| Property | Value |
|----------|-------|
| Columns | Código (immutable) · Texto para la tienda · Política · Activo |
| Edit (inline row form) | Text (10–300, counter, usted voice hint "Escríbalo como lo leerá la tienda."); Policy: radio "Puede volver a solicitar después de [n] días" (0–365) · "Definitivo"; Active toggle |
| New reason | Code (PascalCase, unique; validated live: "Use letras sin espacios, empezando con mayúscula, por ejemplo DataMismatch.") plus the same fields |
| Delete | Not offered. Deactivating is the only removal |
| Last active | Deactivating the only active reason is refused: "Debe quedar al menos un motivo activo." (`RequestValidationFailed`, field-level on the toggle) |
| Save | "Guardar cambios" per row, with a single confirmation when the policy changes: "Cambiar la política de {código} de {antes} a {después}. Aplica solo a rechazos futuros." |

## Page States

| State | When | Appearance | Actions |
|-------|------|------------|---------|
| Loading | Fetch | `skeleton` rows | — |
| Empty | — | Not possible (≥1 active is invariant); the seed has 5 | — |
| Error — validation | Field rules | `field-error` under the field; the row stays in edit | Fix |
| Error — lost race | Another admin saved the same row first | Banner "{admin} cambió este motivo el {fecha}. Revise los valores actuales antes de guardar." The row reloads, and the admin's unsaved edits are shown beside it for re-entry | Volver a editar |
| Error — transport | Save not confirmed | §10 | Actualizar |
| Success | Saved | The row re-renders; live-region confirmation "Motivo actualizado"; history gains a row | — |

---

## Technical Notes

- Saving sends the row's version. A stale version is refused, and the UI shows the lost-race state (no silent overwrite).
- The 5.3 reject dialog reads active reasons at open time. `RejectionReasonUnknown` covers a deactivation between open and confirm.
