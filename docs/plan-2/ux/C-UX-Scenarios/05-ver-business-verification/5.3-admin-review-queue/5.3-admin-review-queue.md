## Overview

**Page Purpose:** Let an admin work Pending applications oldest-first (FR-VER-2), read legal identity in the one audited place (FR-VER-5), and approve or reject with a conditional transition (FR-VER-3, FR-VER-4). A lost race re-renders the decided state and names the winner (NFR-VER-1).

**Success Criteria:**
- The queue never shows legal identity.
- Opening the detail writes exactly one access-log row per read (the page states it).
- A decision is either applied once or refused with who decided and when.

**Entry Points:** Admin rail → Solicitudes; deep link `/admin/solicitudes/<id>` from 1.3 or 5.4.

**Exit Points:** Back to the queue after a decision; 5.4 (the "Ver accesos" link on the detail); 5.5 (the "Gestionar motivos" link inside the reject dialog footer).

## Page Sections

### Section: Queue

**OBJECT ID:** `ver-queue-table`

| Property | Value |
|----------|-------|
| Component | `data-table`; columns Tienda · Ciudad · Presencia (the host plus a truncated path; opens in a new tab) · Espera (age since submittedAt) · Anteriores (prior application count, with the latest outcome in words) |
| Order | Oldest submittedAt first; ties by applicationId. Order is fixed (no column sort) so two admins see the same next item |
| Paging | 25 per page, keyset. Header counter "{n} en revisión" |
| Excluded | legalIdentity, documents, payment instructions |
| Empty | `empty-state`: "No hay solicitudes en revisión." |

### Section: Review Detail

**OBJECT ID:** `ver-review-detail`

| Property | Value |
|----------|-------|
| Read | Loaded via `identity.getApplicationForReview`. One access-log row per load, listing `fieldsRead`. The audit line is shown before any value |
| Documents | `document-viewer`: view-only, no download (NFR-SYS-14). It renders only the sanitized rendition as an image, never the original file (ARCHITECTURE AD-SYS-8 rule 11; the PDF rendition is pending G-5). 10-minute signed link. On expiry the frame shows "El enlace expiró." with "Volver a abrir el documento" (a new read, a new log row) |
| Payment | Account number masked except the last 4 digits (the full value is not needed to decide) |
| History | Prior applications with outcome, reason text, note and decision date. Admin names of prior decisions **are** shown here (admin-only surface) |
| Status | `state-indicator`: En revisión · Aprobada · No aprobada. Decided items render read-only with the deciding admin and `{fecha}` |

### Section: Approve Dialog

**OBJECT ID:** `ver-review-approve`

| Property | Value |
|----------|-------|
| Trigger | `button-primary` "Aprobar" |
| Dialog | "Aprobar la tienda de {nombre}. Sus publicaciones recibirán la insignia de verificación y se abrirá su cuenta de comisión en $0." Buttons: "Cancelar" · "Aprobar tienda" |
| Success | Return to the queue with the live-region confirmation "Solicitud aprobada · {fecha}" (or "Solicitud rechazada · {fecha}") |

### Section: Reject Dialog

**OBJECT ID:** `ver-review-reject`

| Property | Value |
|----------|-------|
| Trigger | `button-destructive` "Rechazar" |
| Reason | Required select of **active** reasons. Each option reads "{texto} · {política}", where the policy is "puede volver a solicitar ya" / "…en {n} días" / "definitivo" |
| Note | Optional textarea, ≤500 characters with a counter. Hint: "La tienda verá esta nota. No incluya números de documento." |
| Consequence line | Updates live with the chosen reason: "Sus publicaciones se retirarán (no se borran). Podrá volver a solicitar desde el {fecha calculada}." or "…La decisión será definitiva para esta cuenta." |
| Confirm | "Rechazar solicitud" |
| Errors | `RejectionReasonUnknown` (the reason was deactivated meanwhile): an inline banner in the dialog, the select reloads, and the note is kept |
| Footer link | "Gestionar motivos" → 5.5 (new tab) |

## Page States

| State | When | Appearance | Actions |
|-------|------|------------|---------|
| Loading | Queue or detail fetch | `skeleton` rows; the detail audit line renders first | — |
| Empty | No Pending | `empty-state` | — |
| Error — load | Fetch failed | §10 load copy | Reintentar |
| Error — lost race | `ApplicationNotPending` | The dialog closes; the detail re-renders read-only with the banner "{admin} ya {aprobó / rechazó} esta solicitud el {fecha}. La vista se actualizó con la decisión." | Volver a Solicitudes |
| Error — not found | `ApplicationNotFound` / not admin | Not-available page | Volver a Solicitudes |
| Error — transport | Decision not confirmed | §10 "No sabemos si…"; on refresh, the detail shows the true status | Actualizar |
| Success | Decision applied | Queue re-renders without the row; live-region confirmation | — |

## Technical Notes

- The detail never caches legal values client-side beyond the view. Navigating away drops them, and back navigation re-reads (and logs).
- The decision buttons send the application's current status version. The server's conditional update is the arbiter; the UI never pre-disables based on a stale poll.
- NFR-VER-3: the queue with 1,000 Pending has p95 ≤ 1 s; the signed URL is issued in ≤ 300 ms. A slower URL shows the viewer's loading state, not a blank frame.
