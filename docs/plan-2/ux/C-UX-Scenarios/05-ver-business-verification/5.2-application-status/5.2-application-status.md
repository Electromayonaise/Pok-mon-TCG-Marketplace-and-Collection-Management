## Overview

**Page Purpose:** Tell the applicant where the latest application stands, what that status allows, and the one next step. For a rejection, show the reason, the note and the reapply condition exactly as snapshotted (FR-VER-7). Host the approved shop's payment instructions for editing (FR-VER-9).

**Success Criteria:**
- Each status renders its microcopy §1.1 copy.
- No internal codes and no admin identities.
- Reapply shows an exact date and time.

**Entry Points:** Success redirect from 5.1; Cuenta → Vender → "Estado de su tienda"; banners on 4.1 and 4.2 ("Ver estado de la solicitud"); the 1.3 support answer (admin tells the applicant where to look).

**Exit Points:** 4.1 ("Publicar mientras tanto"); 7.1 ("Recargar saldo"); 5.1 ("Volver a solicitar"); 4.2.

## Page Sections

### Section: Status Block

**OBJECT ID:** `ver-status-block`

| Property | Value |
|----------|-------|
| Pending | Headline and body from §1.1; "Solicitud enviada el {fecha}"; action "Publicar mientras tanto" → 4.1 |
| Approved | §1.1 copy; `verification-status-badge` verified; action "Recargar saldo" → 7.1 (the COM "never funded" line shows until the first confirmed top-up) |
| Rejected — cooldown | §1.1 copy with reason text (§1.2 snapshot), the note, and `{fecha}`. Before the instant, no action (the date is the answer). At or after it, "Volver a solicitar" → 5.1 |
| Rejected — barred | §1.1 barred copy; no action |
| No application | "Aún no ha enviado una solicitud para vender como tienda." with the action "Empezar solicitud" → 5.1 |

### Section: Listings Consequence

**OBJECT ID:** `ver-status-listings`

| Property | Value |
|----------|-------|
| Content | One line per status, with counts: Pending "{n} publicaciones visibles sin insignia; aún no se pueden comprar." · Rejected "{n} retiradas, no borradas…" · Approved "{n} con insignia." plus the pause line if the balance is ≤ 0 |
| Messages (Pending) | "Los compradores pueden escribirle dentro de TEZG con un aviso de «tienda aún no verificada»." (FR-MSG-4) |

### Section: Payment Instructions (Approved only)

**OBJECT ID:** `ver-status-payment`

| Property | Value |
|----------|-------|
| View | `payment-details-block` exactly as buyers will see it |
| Edit | "Editar datos de pago" opens an inline form with the 5.1 field rules. The note reads "Los cambios aplican a pedidos nuevos. Los pedidos que ya existen conservan los datos con los que se hicieron." (FR-VER-9) |

### Section: Application History

**OBJECT ID:** `ver-status-history`

| Property | Value |
|----------|-------|
| Content | Newest first: the submission date, then the status in words (En revisión · Aprobada · No aprobada) with the decision date. No admin names and no reason codes |

## Page States

| State | When | Appearance | Actions |
|-------|------|------------|---------|
| Loading | Fetch | Skeleton status block | — |
| Empty | No application | As in the "No application" row | Empezar solicitud |
| Error | Fetch failed | §10 load copy | Reintentar |

---

## Technical Notes

- All text comes from the application's snapshot (reason text and policy at decision time), not from the current policy table (FR-VER-4).
- The page never shows legal identity values, not even the applicant's own (they are only readable through the admin review, FR-VER-5).
