## Overview

**Page Purpose:** Collect a business application with explicit consent to process legal identity (AD-13). Report every shape issue at once, then apply the first-fail business rules (pending, approved, cooldown, barred, exclusivity) as one banner that replaces the submit button (FR-VER-1, FR-VER-6).

**Success Criteria:**
- A valid submission creates exactly one `Pending` application and lands on 5.2.
- An invalid one keeps every typed value and every selected file.
- A date gate is shown, never hidden.

**Entry Points:**
- Cuenta → Vender → "Vender como tienda";
- 5.2 → "Volver a solicitar";
- 4.1 → rejected-business notice → 5.2 → here.

**Exit Points:** 5.2 (success); Aviso de privacidad (new tab).

## Page Sections

### Section: Shop

**OBJECT ID:** `ver-apply-shop`

| Property | Value |
|----------|-------|
| Fields | Name (2–80); City (native select of supported cities plus "Otra", which reveals free text of 2–60); Instagram or website (https, ≤2.048) |
| Messages | Microcopy §1.3 |

### Section: Legal Identity

**OBJECT ID:** `ver-apply-legal`

| Property | Value |
|----------|-------|
| Type | Radio: NIT · Cédula de ciudadanía. The note "Por ahora no aceptamos cédula de extranjería." (out of scope, §5) |
| Number | CC: 6–10 digits. NIT: base of 6–10 digits plus a separate one-digit check field |
| Live check | After both NIT parts are entered, the client computes DIAN mod-11 and shows either "✓ Dígito de verificación correcto" or the field error. The server re-checks (truth) |
| Documents | `upload-dropzone`, 1–3 files (PDF, JPG, PNG, ≤5 MB each), with per-file progress. The hint is "Por ejemplo, su RUT y una foto de su cédula." |
| Privacy | Values in this section are never echoed in banners, summaries or confirmations (NFR-SYS-2). The error summary links to the field, but shows only the message |

### Section: Payment Instructions

**OBJECT ID:** `ver-apply-payment`

| Property | Value |
|----------|-------|
| Fields | Bank (select); account type (Ahorros · Corriente); account number (6–20 digits); holder name; optional QR image (same file rules) |
| Note | "Los compradores verán estos datos para pagarle cuando su tienda esté verificada." |

### Section: Consent

**OBJECT ID:** `ver-apply-consent`

| Property | Value |
|----------|-------|
| Control | Unchecked checkbox: "He leído el [aviso de privacidad] (versión {versión}) y autorizo a TEZG a tratar el número y los documentos legales de mi tienda solo para verificarla." |
| Stale version | If the notice changed while the form was open: "El aviso de privacidad cambió mientras llenaba el formulario. Léalo de nuevo y acéptelo para continuar." The box is unchecked again |

### Section: Submit Area

**OBJECT ID:** `ver-apply-submit`

| Property | Value |
|----------|-------|
| Default | `button-primary` "Enviar solicitud" |
| Replaced by banner (first-fail) | `ApplicationAlreadyPending` → action "Ver estado"; `AlreadyVerifiedBusiness` (VER submit); `IndividualSellerProfileAlreadyComplete` (VER submit, UX-A-2); `ReapplicationCooldownActive` with `{fecha}` (date and time); `ReapplicationBarred` (the form is not rendered; only the banner shows, with "Ver solicitud") |
| Gate timing | While the cooldown is active, the banner is shown on load and the form can still be filled in. At the exact instant (checked against server time on focus and every 60 s), the button replaces the banner. A submit sent 1 s early is refused server-side with the same banner |

## Page States

| State | When | Appearance | Actions |
|-------|------|------------|---------|
| Loading | Initial fetch (status, gate) | Skeleton sections | — |
| Empty | Not applicable | A form has no list that could be empty; the blank form is the default state below | — |
| Error — validation | Shape issues | One summary ("Revise {n} campos antes de continuar:") plus field errors; focus moves to the summary; files are kept | Fix |
| Error — domain | First-fail rule | Banner replaces the submit area | Per the banner |
| Error — upload | A file fails | Dropzone error state on that file only | Reemplazar |
| Error — transport | Submit not confirmed | Microcopy §10 "No sabemos si…" | Actualizar |
| Success | Created | Redirect to 5.2 with the live-region confirmation "Solicitud enviada." | — |

---

## Technical Notes

- Uploads go to private storage paths first. They attach to the application only on a successful submit, and orphans are swept (NFR-VER-4 budget: ≤10 s for 3×5 MB at 10 Mbps).
- The form state is kept per device (without files) if the session expires. Files must be selected again, and a line says so.
- No field in section 2 is sent to analytics or logs.
