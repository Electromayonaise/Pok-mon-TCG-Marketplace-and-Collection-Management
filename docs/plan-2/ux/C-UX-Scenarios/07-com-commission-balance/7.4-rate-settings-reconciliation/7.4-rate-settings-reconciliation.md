## Overview

**Page Purpose:** Two admin jobs about the integrity of commission money:
1. Schedule a commission rate from now or a future time without changing any past charge (FR-COM-7).
2. Check that every balance equals its top-ups minus its deductions, with no gap in the sequence, and see what the daily job found (FR-COM-8).

**Success Criteria:**
- The rate in force and any scheduled rate are both visible, with absolute start times.
- The history of rates can't be edited or deleted from the UI, and every row names who set it.
- A reconciliation result is readable per account, and a discrepancy links to the ledger it concerns.

**Entry Points:** Admin rail → Comisiones → Tarifa y conciliación; the daily-job alert in the admin header ("La conciliación encontró {n} diferencias").

**Exit Points:** 7.2 admin variant for any account in the report; none for rate-change audit rows: the rate history on this page names the actor and time of each change (11.4 covers moderation only, FR-REP-6).

## Page Sections

### Section: Rate Summary

**OBJECT ID:** `com-rate-summary`

| Property | Value |
|----------|-------|
| In force | "Vigente: {tasa} ({pb} pb) desde {fecha}" |
| Scheduled | "Programada: {tasa} ({pb} pb) desde {fecha}", only when a future row exists |
| Action | `button-primary` "Programar nueva tarifa" opens the form below |

### Section: Rate Form

**OBJECT ID:** `com-rate-form`

| Property | Value |
|----------|-------|
| Rate | Integer basis points, 0–10.000, with a live percent preview "= 8,5 %". Out of range: "La tarifa debe estar entre 0 y 10.000 pb (0 % a 100 %)." Non-integer: "Use un número entero de puntos básicos." |
| Start | "Desde": Ahora / Fecha y hora (Bogotá time). A past time: "La fecha de inicio no puede estar en el pasado." |
| Worked example | Read-only line computed by the server for a $45.000 order: "Un pedido de $45.000 pagaría {c}." It uses the FR-COM-5 rounding |
| Submit | Opens a `<dialog>` because a setting is append-only and can't be withdrawn from the UI: "¿Programar {tasa} desde {fecha}?" / "Aplica a comisiones que se cobren desde el {fecha}. Los cobros anteriores no cambian." Actions "Programar tarifa" / "Cancelar" |
| After | The history gains the row; the summary shows it as Programada or Vigente; the live region repeats the dialog body |

### Section: Rate History

**OBJECT ID:** `com-rate-history`

| Property | Value |
|----------|-------|
| Component | `data-table`, newest start first |
| Columns | Tarifa · Desde · Definida por · Registrada |
| Row state | `state-indicator`: confirmed "Vigente", pending "Programada", inert "Anterior" |
| Editing | None. Rows have no edit or delete action (append-only). A mistaken future rate is replaced by scheduling another row with the same or an earlier start |

### Section: Reconciliation

**OBJECT ID:** `com-reconcile`

| Property | Value |
|----------|-------|
| Last daily run | "Última ejecución diaria: {fecha} · {n} diferencias". When n > 0, the line uses the refusal-tone `explainability-banner` and the admin header shows the alert until a later run reports 0 |
| Run now | `button-secondary` "Conciliar ahora" runs `commission.reconcile()` for all accounts. While running: "Conciliando {n} cuentas…". Optional account filter |
| Report | `data-table`: Tienda · Saldo · Recargas · Comisiones · Diferencia · Secuencia. Default sort: rows with a difference or a gap first |
| Row OK | "{tienda} · saldo {saldo} = recargas {recargas} − comisiones {comisiones} · secuencia continua ✓" (screen-reader text for the row) |
| Row with difference | Difference in `status-error` text with the sign, e.g. "−$1.000", and the row explanation "El saldo guardado ({saldo}) no coincide con recargas − comisiones ({calculado})." → "Ver movimientos" |
| Row with a gap | "Falta el movimiento #{seq} en la secuencia." → "Ver movimientos" |

The page reports discrepancies. It never corrects a balance, because refunds and adjustments are out of scope.

## Technical Notes

- The rate used for a deduction is the one in force at `commissionTriggeredAt` (FR-COM-5, FR-COM-7). The history is enough to explain any past deduction, and 7.2's row detail shows the rate each deduction used.
- Every rate row writes an audit entry with the actor, the time and the before/after values (FR-COM-7, NFR-SYS-8).
- Reconciliation reads stored `balanceCop` and the ledger sums as integers (NFR-COM-4). No figure on this page comes from client arithmetic.
