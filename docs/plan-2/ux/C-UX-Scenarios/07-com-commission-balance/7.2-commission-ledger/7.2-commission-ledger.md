## Overview

**Page Purpose:** Show every peso that entered or left a commission balance, in order, so that the owner can explain any change to their balance and the admin can review any account (FR-COM-8). Every deduction links to its order and says what triggered it.

**Success Criteria:**
- For any line, the reader can tell what happened, when, which order it belongs to, the rate and base used, and the balance after it.
- Adding the visible lines from the start reproduces the balance shown in the header.
- The admin can list every buyer-closed charge in one filter.

**Entry Points:**
- Business: 6.3 "Ver movimiento" (the page opens scrolled to that order's line, highlighted); 7.1 "Ver movimientos"; desk rail.
- Admin: rail → Comisiones → account search; 7.4 reconciliation result → "Ver movimientos"; 1.3 account detail.

**Exit Points:**
- 6.3 or the admin order lookup ("Ver pedido");
- 7.1 ("Ver saldo", business);
- support ("Contactar a soporte" on a buyer-closed line).

## Page Sections

### Section: Header

**OBJECT ID:** `com-ledger-header`

| Property | Value |
|----------|-------|
| Business | Compact `commission-balance-card`: balance + state label + "Recargar saldo" → 7.1 |
| Admin | Account picker (search by shop name or business id), the same compact card read-only, and "Conciliar esta cuenta" → runs `commission.reconcile(businessId)` and shows the result inline (same copy as 7.4) |

### Section: Filters

**OBJECT ID:** `com-ledger-filters`

| Property | Value |
|----------|-------|
| Type | Todos · Recargas · Comisiones |
| Date range | From / to, in Bogotá time |
| Trigger (admin only) | Todos · Pago confirmado (`businessConfirmed`) · Cierre del comprador (`buyerClosed`). With "Cierre del comprador" and no account chosen, the table lists the matching lines across all accounts, with a Tienda column (FR-COM-8) |
| URL | Filters are kept in the query string so a filtered view can be shared between admins |

### Section: Ledger Table

**OBJECT ID:** `com-ledger-table`

| Property | Value |
|----------|-------|
| Component | `ledger-table` |
| Order | Newest first (by `seq`); 50 per page |
| Columns | Fecha · Movimiento · Monto · Saldo después · (admin) Disparador · (admin) Seq |
| Account opened | "Cuenta abierta" · $0 · $0 (the seq-0 line, FR-COM-1) |
| Top-up | "Recarga {referencia}" · +{monto}; the admin sees "Confirmada por {admin}" |
| Deduction, `businessConfirmed` | §5 ledger line "Comisión del pedido {pedido} ({tasa} de {base})" + "Ver pedido" |
| Deduction, `buyerClosed` | Same first line, then the §5 buyer-closed line and "Contactar a soporte". The admin sees the trigger in its column |
| Threshold markers | When a line crossed zero, a `state-indicator` sub-line: "Publicaciones pausadas" (inert) or "Publicaciones reactivadas" (confirmed). Only on the crossing line, so the reader sees exactly one per crossing |
| Highlight | Arriving from 6.3 scrolls to and highlights the order's line with `surface-raised` for the session; focus lands on it |

### Section: Row Detail

**OBJECT ID:** `com-ledger-detail`

| Property | Value |
|----------|-------|
| Trigger | Enter or click on a row expands it in place |
| Deduction | Order total, rate in bps and percent, the formula result "floor((180.000 × 800 + 5.000) / 10.000) = 14.400", trigger time (`commissionTriggeredAt`), trigger name in words |
| Top-up | Reference, submitted time, decided time, the admin's name, comprobante link (admin only; opens `document-viewer`) |

## Technical Notes

- The table is read-only. No command runs from this page except the admin's reconcile.
- "Saldo después" is the stored `balanceAfter` of each entry, not a client-side running sum (NFR-COM-4).
- Buyer-closed charges are shown as final. OQ-3 was resolved at the Phase 1 gate as "charge on whichever comes first, business confirmation or buyer close, once per order"; the page shows the charge and the support link, and it offers no reversal because refunds are out of scope.
