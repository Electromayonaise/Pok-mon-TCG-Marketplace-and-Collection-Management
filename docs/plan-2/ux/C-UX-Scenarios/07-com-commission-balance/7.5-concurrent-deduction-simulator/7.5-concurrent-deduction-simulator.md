## Overview

**Page Purpose:** Prove, on the fixture adapters, the COM guarantees that are impossible to see in a normal session: exactly one deduction per order whatever the delivery order, the integer rounding, and exactly one threshold event per crossing under concurrency. Each run ends in a pass or fail verdict that is checked against the invariants, not left to be read from a chart.

**Success Criteria:**
- The NFR-COM-1 preset runs ×100 and reports PASA only when every iteration holds all invariants.
- A failing iteration can be opened and replayed from its seed.
- Every command shows its Decision, its JSON and the resulting account state side by side.

**Entry Points:** The `/dev` index; a link from 6.4 ("Ver efecto en comisiones").

**Exit Points:** 6.4 (the order that produced a deduction); the `/dev` index.

## Page Sections

### Section: Console Header

**OBJECT ID:** `com-sim-header`

| Property | Value |
|----------|-------|
| Banner | "Consola de desarrollo · datos de prueba" |
| Actor switcher | Sistema (event publisher) · Andrés (business) · Sebastián (admin) |
| Virtual clock | +1 h · +48 h · +7 d · fecha exacta. The rate in force follows the clock, so a rate change scheduled in 7.4's fixture can be crossed deliberately |
| Reset | "Restablecer cuenta" returns the fixture account to the preset's starting state |

### Section: Presets (Plantillas)

**OBJECT ID:** `com-sim-presets`

| Preset | Setup | Action | Invariants checked |
|--------|-------|--------|--------------------|
| **NFR-COM-1: dos pedidos simultáneos + duplicado** | Balance $5.000, rate 800 bps, two $45.000 orders | Both `OrderPaymentConfirmedByBusiness` delivered concurrently, plus one duplicate of the first, ×100 | Final balance −$2.200; exactly 2 deduction entries of $3.600; exactly 1 `CommissionBalanceExhausted`; 0 Replenished; `seq` continuous; balance = Σ top-ups − Σ deductions |
| **Disparadores simultáneos** | One order; balance $50.000 | `OrderPaymentConfirmedByBusiness` and `OrderClosed` for the same order delivered concurrently, ×100 | Exactly 1 entry; its `trigger` is the one with the earlier `commissionTriggeredAt`; balance −1 × commission |
| **Redistribuir ×3** | COM-S2: the $180.000 order, balance $50.000 | Deliver the same event 3 times | 1 entry of $14.400; balance $35.600 |
| **Vectores de redondeo** | Rate 800 bps | Totals 45.000, 45.006, 45.007, 1 | Commissions 3.600, 3.600, 3.601, 0 (FR-COM-5) |
| **Recarga que no alcanza** | Balance −$25.000 | Confirm a $20.000 top-up | Balance −$5.000; no Replenished; the 7.1 still-short copy with "$5.001" |
| **Aleatoria (NFR-COM-2)** | 10.000 random top-ups and deductions with 20 % duplicates, with a shown seed | Run | Difference of $0; `seq` continuous |

Each preset has "Ejecutar" and "Ejecutar ×100" (×1 for the random preset). The seed of every run is shown and can be pasted back to replay it.

### Section: Event Injector

**OBJECT ID:** `com-sim-inject`

| Property | Value |
|----------|-------|
| Type | `BusinessApplicationApproved` · `OrderPaymentConfirmedByBusiness` · `OrderClosed` · top-up confirm (through the manual adapter) |
| Fields | orderId (default: a new cuid2), total COP, trigger time (default: the virtual clock) |
| Actions | "Entregar" · "Duplicar la última" · "Entregar fuera de orden" (sends the second event of a pair first) |
| Output | Decision → JSON → state view (the H console pattern) |

### Section: Account State

**OBJECT ID:** `com-sim-state`

| Property | Value |
|----------|-------|
| Summary | Balance, state (`state-indicator`), last `seq`, rate in force |
| Ledger | `ledger-table` with seq, type, amount, balance after, trigger, `commissionTriggeredAt` |
| Events | Counters for Exhausted and Replenished published in this run, plus the recording subscriber's log (what `listings` would have received, with `ledgerSeq`) |

### Section: Run Result

**OBJECT ID:** `com-sim-result`

| Property | Value |
|----------|-------|
| Component | `race-simulator` result panel |
| Verdict | "PASA {n} / FALLA {m}" and one line per invariant with ✓ or ✗ plus the observed value |
| Failure | Each failing iteration is listed with its seed and the first broken invariant, e.g. "Iteración 37: 2 eventos Exhausted (se esperaba 1)". "Reproducir" replays it step by step |
| Timing | p95 deduction and confirmation times of the run, shown next to the NFR-COM-3 targets (≤ 200 ms and ≤ 800 ms) as information. The CI test, not this page, is the gate |

## Technical Notes

- The console calls the same `commission` handlers the event subscribers use, through the fixture publisher. It never writes to the ledger directly, so a pass here is evidence about the real code path.
- Concurrency is real: the ×100 presets issue the deliveries in parallel against the database, not in sequence.
- The page is excluded from production builds by route configuration, so the banner is a second line of defence, not the first.
