## Overview

**Page Purpose:** Let an admin find a review or a listing, hide it with a policy reason and a note, and undo that later, with nothing ever deleted (FR-REP-4, FR-REP-5, FR-REP-6). The page also lists everything currently hidden.

**Success Criteria:**
- The dialog restates what will be hidden and what happens next, before the admin confirms.
- A hide shows its effect in words at once: the target's new rating for a review, or its removal from browse for a listing.
- A double hide or a double unhide is an explained no-op that names the earlier action; it never errors and never writes a second log row.
- Hidden items stay findable here with their reason, actor and time.

**Entry Points:** Admin rail → Moderación; "Ver en moderación" from a row of 11.4.

**Exit Points:** 11.4 ("Ver auditoría"); the public profile 11.2 or card detail 2.2 in a new tab ("Ver en el sitio", visible items only).

| Property | Value |

### Section: Results Table

**OBJECT ID:** `rep-mod-table`

| Property | Value |
|----------|-------|
| Component | `data-table`, 25 per page, keyset |
| Review columns | Fecha (created) · Autor · Destino (the reviewed seller) · ★ (rating) · Estado |

## Technical Notes

- AD-12: there is no shared moderation table. Reviews are searched through a REP admin query and listings through a `listings` admin query; the page switches data source with the type. Each module's hide and unhide write their own log (`ReviewModerationLog`, `ListingModerationLog`).
- Hide and unhide are conditional updates. The response of a no-op carries the existing hide (or unhide) so the banner can cite it; no log row is written (the REP-S4 audit shows each action once).
- The "La calificación de {destino} ahora es…" message uses the aggregate returned by the hide command from the same transaction, not a separate read. The browser never computes it.
- NFR-REP-2: the hide is effective on the next public read (no cache). NFR-REP-3: no delete affordance exists anywhere on the page, and the API exposes none.
- NFR-REP-1 (a hide racing a new review ×100 keeps `count` and `sum` equal to the visible set) is an integration test. REP has no H console, so this page does not host a prober.
- A hidden listing's open orders, accepted trades and open offers are untouched (FR-REP-5 [ASSUMPTION], A-48); the panel's "Pedidos u ofertas abiertos: {n}" line tells the admin they exist.
- Admin search over listing descriptions and review text is exact-substring, case- and accent-insensitive [ASSUMPTION: the PRD does not specify admin search semantics; Phase 3 fixes the index].
