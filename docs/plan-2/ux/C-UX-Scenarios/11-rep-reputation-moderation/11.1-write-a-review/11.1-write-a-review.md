## Overview

**Page Purpose:** Let a buyer rate a seller from 1 to 5 stars with an optional text, but only when the rules allow it: a closed purchase for a verified shop (FR-REP-1), a complete profile for an individual seller (FR-REP-2). When the rules don't allow it, say why before the person types anything.

**Success Criteria:**
- Eligibility is checked when the page opens; a refused caller never sees an input they can't submit.
- The refusal for a paid-but-not-closed order says that paying isn't enough and links to the order.
- A caller who already reviewed this seller lands in edit mode, never on a `DuplicateReview` error.
- The page says which kind of review this is (verified purchase, or not linked to purchases) before the rating.

**Entry Points:** 6.2 "Ahora puedes reseñar a {tienda}" (closed order); 11.2 "Escribir una reseña" / "Editar tu reseña"; the `DuplicateReview` action "Editar mi reseña".

**Exit Points:** 11.2 of the same seller (after publishing or saving, and "Cancelar"); 6.2 ("Ver pedido" on the refusal).

## Page States

| State | When | Appearance | Actions |
|-------|------|------------|---------|
| Loading | Eligibility and existing-review read | `skeleton` header and form | — |
| Empty | Eligible, with no review yet | Not a separate state: it is "Eligible, new" below (header, note and an empty form). The page lists no other reviews | Publicar reseña, Cancelar |
| Eligible, new | No review yet, rules pass | Header, note, empty form | Publicar reseña, Cancelar |
| Eligible, edit | The caller already has a visible review of this seller | Prefilled form | Guardar cambios, Cancelar |
| Refused | `NotVerifiedPurchaser` or `TargetNotFound` on load | Eligibility banner instead of the form | Ver pedido (paid case) |
| Hidden own review | The caller's review of this seller is hidden | Tombstone card, no form | ← {nombre} |
| Submitting | Request in flight | Primary disabled with a spinner after 300 ms | — |
| Refused on submit | The server refuses although the page allowed it (a second tab, or the shop stopped being Approved) | The same banner as on load replaces the form; the typed text stays in a read-only block with "Copiar" | Per banner |
| `DuplicateReview` on submit | A review was created in another tab | "Ya reseñaste a {nombre}. Puedes editar tu reseña." | Editar mi reseña (reloads in edit mode; the typed text stays in a read-only block with "Copiar") |
| `ReviewNotFound` on save | Edit of a review that no longer resolves | "Esta reseña ya no está disponible." | ← {nombre} |
| Success | Published or saved | Navigates to 11.2; live region "Publicaste tu reseña de {nombre}." / "Guardaste los cambios de tu reseña." | — |
| Not available | `userId` has no public seller profile | Not-available page: "No encontramos este perfil." | Ir al catálogo |
| Error — network | Request did not complete | §10 copy; the form keeps rating and text | Reintentar |

## Technical Notes

- The load-time eligibility check is a read (a REP query that consults `orders.hasClosedPurchase` and `identity.getReviewTarget`); Phase 3 names it. The submit command re-checks everything: NFR-REP-1's 100/100 refusal is a server property, and the page's check is only a courtesy.
- "Ver pedido" needs the order the refusal cites. The `NotVerifiedPurchaser` citation carries `latestState`; Phase 3 adds the order id to it so the link can open 6.2 directly, or the link opens Actividad → Pedidos filtered to the shop.
- Edit sets `editedAt` and keeps `purchaseVerified` as snapshotted at creation (FR-REP-1).
- The UI does not offer editing a hidden review [ASSUMPTION: the PRD does not say whether an edit is allowed while hidden; logged in `review-ux-edge-cases.md`].
- The rating and text are sent as typed; the text is stored as plain text and rendered escaped on 11.2.
