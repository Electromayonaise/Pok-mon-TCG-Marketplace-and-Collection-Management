## Overview

**Page Purpose:** Show every hide and unhide of reviews and listings, once each, with who, when, why and on what (FR-REP-6, NFR-SYS-8), combining the two modules' logs without a shared table (AD-12).

**Success Criteria:**
- Every hide and unhide appears exactly once (FR-REP-6 acceptance); no-ops never appear.
- Filters by type, reason and date answer "what was hidden for Acoso this week?" in one step.
- The log is read-only; nothing on the page edits or deletes a row.

**Entry Points:** Admin rail → Auditoría → "Moderación"; "Ver auditoría" on 11.3.

**Exit Points:** "Ver en moderación" on a row → 11.3 with the item's panel open.

## Page Sections

### Section: Filters

**OBJECT ID:** `rep-audit-filters`

| Property | Value |
|----------|-------|
| Tipo | Todos · Reseñas · Publicaciones |
| Motivo | Todos, then the §9.1 labels; with a type chosen, only that type's reasons |
| Fechas | "Desde" and "Hasta", inclusive, as calendar days in Bogotá time |
| URL | All filters and the page live in the URL; reload and back restore them |
| Clear | "Quitar filtros" appears when any filter is set |

### Section: Audit Table

**OBJECT ID:** `rep-audit-table`

| Property | Value |
|----------|-------|
| Component | `data-table`, 50 per page, keyset; "Página {p} de {n}" |
| Columns | Fecha (`{fecha}` with time) · Tipo (Reseña / Publicación) · Acción (`state-indicator`: hollow dot "Ocultó" · filled dot "Mostró de nuevo", always with the word) · Motivo (the §9.1 label; "—" for an unhide) · Contenido (review: "{autor} → {destino}"; listing: "«{título}» de {vendedor}") · Administrador · Nota (preview, or "—") |
| Order | Newest first, `aria-sort="descending"` on Fecha; ties broken by module then row id, so paging is stable |
| Row action | Opens the detail panel; Esc closes it and returns focus to the row |
| Empty | `empty-state`: "No hay acciones de moderación con estos filtros." with "Quitar filtros" |
| Export | None [ASSUMPTION: not required by FR-REP-6] |

### Section: Row Detail

**OBJECT ID:** `rep-audit-detail`

| Property | Value |
|----------|-------|
| Content | The full row: date and time, type, action, reason, the full note, the admin, and the content reference as in the table |
| Snapshot | For a review, the rating and text as they were at the time of the action; for a listing, the title and price [ASSUMPTION: the log row carries a content snapshot, per NFR-SYS-8 `before?`; Phase 3 decides the fields] |
| Link | "Ver en moderación" → 11.3 with the type set and the item's panel open (where its current status and full history show) |

## Technical Notes

- AD-12 / NFR-SYS-8: the page reads `ReviewModerationLog` and `ListingModerationLog` through each module's public query and merges them by time. No combined table exists, and nothing is copied between modules.
- Paging across two sources: each query is asked for the next 50 after the shared cursor (time, module, id), and the page takes the first 50 of the merge. "Página {p} de {n}" uses the sum of the two filtered counts.
- A no-op hide or unhide writes no log row (11.3), so each effective action appears exactly once (FR-REP-6 acceptance).
- Rows are append-only (NFR-SYS-8, NFR-REP-3): no edit or delete affordance, and the API exposes none.
- Other admin actions (VER decisions, top-ups, rate changes, feed runs) stay in their own modules' pages; this page covers moderation only.
