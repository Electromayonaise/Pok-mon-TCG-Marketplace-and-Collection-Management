## Overview

**Page Purpose:** Show how a seller is rated and what kind of rating it is: an exact average of visible reviews with a stated rounding rule, the count, the provenance label, and the reviews themselves, newest first.

**Success Criteria:**
- The average, the count and the list come from one read and never disagree (FR-REP-3).
- "Aún no tiene reseñas" replaces the average when there are none; "0,0" never appears.
- The provenance label is always visible next to the average.
- A hidden review is shown only to its author, as a tombstone; everyone else sees no trace of it (FR-REP-7).

**Entry Points:** Seller name on 2.2 and on listing detail; 6.2 shop name; 11.1 after publishing; Cuenta → Reseñas (own profile).

**Exit Points:** 11.1 ("Escribir una reseña" / "Editar tu reseña"); back to the page it came from.

## Page Sections

### Section: Seller Header

**OBJECT ID:** `rep-profile-header`

| Property | Value |
|----------|-------|
| Name | Shop name (business) or display name (individual) |
| Kind line | Business: `verification-badge` "tienda verificada" · city. Individual: "Vendedor individual" |

### Section: Rating Summary

**OBJECT ID:** `rep-profile-summary`

| Property | Value |
|----------|-------|
| Component | `rating-summary` |
| Average | The server's integer tenths formatted with a decimal comma ("4,3"). Stars: `round(average)` filled glyphs of 5, `aria-hidden`; the text equivalent "4,3 de 5" is the accessible name |
| Count | "{n} reseña" / "{n} reseñas" |
| Provenance | Business: "De compras verificadas". Individual: "Las reseñas no están ligadas a compras" |
| No reviews | "Aún no tiene reseñas" in place of the average, stars and count; the provenance label stays |
| Action | `button-primary` "Escribir una reseña" → 11.1, or "Editar tu reseña" when the caller has one. Not shown on the caller's own profile, for a shop that isn't Approved, or to anonymous callers (they see "Inicia sesión para reseñar", which returns here after sign-in) |

### Section: Review List

**OBJECT ID:** `rep-profile-reviews`

| Property | Value |
|----------|-------|
| Component | `review-card` per review |
| Card content | Stars + "{n} de 5"; text (omitted when empty); date "{dia}"; "Compra verificada" when `purchaseVerified`; "editada" when `editedAt` is set |
| Caller's own review | Labelled "Tu reseña" and listed in its date position |
| Hidden, caller is the author | The caller's card in the `hidden-for-author` state: inert banner "Oculta por moderación de TEZG: {motivo}." It is not counted in the summary |
| Hidden, anyone else | Absent; no placeholder and no gap marker |
| Order and paging | Newest first; 20 per page; "Ver más reseñas" appends the next 20 and refreshes the summary from the same read |
| Reviewer identity | Not shown: FR-REP-7 lists rating, text, date and markers only |

## Technical Notes

- One read returns `{ count, averageTenths | null, provenance, page[] }` from one snapshot (FR-REP-3). The browser never sums or divides ratings; it inserts the decimal comma.
- NFR-REP-2: p95 ≤ 300 ms for the summary plus the first page; no cache, so a hide shows on the next read. An already-rendered page is not updated in place.
- Paging is keyset by (`createdAt` desc, id desc), so appending never repeats or skips a review when a new one arrives meanwhile; the summary returned with each page is the current one.
- The author's hidden card comes from a separate "my review of this target" read, so the public list query never returns hidden rows (FR-REP-7 acceptance).
- Admins see the public view here; hidden content is reviewed on 11.3.
