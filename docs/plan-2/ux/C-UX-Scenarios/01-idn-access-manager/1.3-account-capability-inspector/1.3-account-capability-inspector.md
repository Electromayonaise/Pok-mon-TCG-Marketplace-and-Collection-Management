## Overview

**Page Purpose:** Let Sebastián answer "what can this account do, and why?" with the derived trace (FR-IDN-5), and look up the account's orders read-only for support (FR-ORD-10). Both reads are audited.

**Success Criteria:**
- The trace shows every FR-IDN-1 capability with its source facts and timestamps.
- No `legalIdentity` value is ever displayed.
- An audit row is written per trace read and per order lookup.

**Entry Points:**
- Admin rail → Cuentas;
- links from 5.3 ("Ver capacidades de la cuenta"), 11.3 and 7.3 (the account name).

**Exit Points:** 5.2 admin view of the application (via 5.3), 7.2 admin ledger filtered to the account, and 11.4, the moderation audit (filtered by type, reason and date, FR-REP-6; there is no per-account filter).

## Page Sections

### Section: Account Search

**OBJECT ID:** `idn-inspector-search`

| Property | Value |
|----------|-------|
| Component | Search input plus `button-secondary` |
| Behavior | Exact email or account id; there is no fuzzy search, to limit browsing. Zero matches: "No hay cuentas con ese correo o id." |

### Section: Account Header

**OBJECT ID:** `idn-inspector-header`

| Property | Value |
|----------|-------|
| Content | Display name, seller kind (words), application status via [`components.state-indicator`](../../../DESIGN.md), email masked as `a•••@dominio`, created date |
| Rule | Never shows `legalIdentity` (NIT/CC, documents) or the phone (NFR-SYS-2) |

### Section: Capabilities Tab

**OBJECT ID:** `idn-inspector-trace`

| Property | Value |
|----------|-------|
| Component | [`components.capability-trace`](../../../DESIGN.md) |
| Content | One line per capability: `canBuy`, `canListAsIndividual`, `canListAsBusiness`, `isVerifiedBusiness`, `canReceiveInAppMessages`, `canModerate`, then `sellerKind`. Each has a human phrase (usted), fact sub-lines with timestamps, and "Ver ids" to reveal the raw ids |
| Behavior | Opening the tab calls `traceCapabilities` and writes `CapabilityAuditRead`. The note "Esta consulta queda registrada en la auditoría." is always visible above the trace |

### Section: Orders Tab (FR-ORD-10)

**OBJECT ID:** `idn-inspector-orders`

| Property | Value |
|----------|-------|
| Component | [`components.data-table`](../../../DESIGN.md), 25 per page, newest first |
| Columns | Order id · counterpart shop or buyer name · created · status (FR-ORD-6 combination, in words) · last fact at |
| Behavior | Read-only; no confirm, cancel or edit controls. Opening the tab writes an audit row. A row expands to the three facts with timestamps; comprobante files are not viewable here |
| Support contact | Footer shows the configured support contact (config value), as buyers see it |

## Page States

| State | When | Appearance | Actions |
|-------|------|------------|---------|
| Empty (no search yet) | First load | "Busque una cuenta por correo o id para ver qué puede hacer y por qué." | Search |
| Loading | Trace or orders fetch | `components.skeleton` rows | — |
| Zero results | No account matches | Inline "No hay cuentas con ese correo o id." | Edit search |
| Error | Fetch failed | Banner "No pudimos cargar la cuenta en este momento. Ya quedó registrado; vuelva a intentarlo en unos segundos." | Reintentar |
| Success — trace | Trace loaded | As in the layout | Switch tab |
| Success — no orders | The account has no orders | "Esta cuenta no tiene pedidos." | — |
| Not available | Non-admin session | Standard Not-available page | Ir al inicio |

## Technical Notes

- The trace text is generated server-side (FR-IDN-5: "rendered in the TEZG tone"). The page does not re-derive capabilities.
- Every capability line cites at least one fact (acceptance for FR-IDN-5). A missing fact is a server bug, shown as "Sin hecho de origen: repórtelo" in `status-error` text, and never hidden.
- Cooldown instants render per ADD-§2.7 with date and time (`8 oct 2026, 10:00 a. m.`), because the gate opens at that exact instant; the fact sub-line keeps the ISO timestamp in `typography.code`.
