## Overview

**Page Purpose:** Exercise every public IDN procedure against the seed fixtures. Two proofs matter most:
- capabilities are derived from facts (FR-IDN-1);
- exclusivity holds under a real concurrent race (FR-IDN-4, NFR-IDN-2).

**Success Criteria:**
- A developer sees `derivedFrom` for any fixture account in one call.
- A client-asserted role is visibly refused.
- The race template shows exactly one winner on every run, with a running tally.

**Entry Points:** `/dev` index → "IDN · Capacidades"; deep link `/dev/idn?fixture=<id>&proc=<name>`.

**Exit Points:** "Abrir en inspector (1.3)" for the same fixture account, where admin fixtures exist.

## Page Sections

### Section: Console Banner & Clock

**OBJECT ID:** `idn-explorer-banner`

| Property | Value |
|----------|-------|
| Component | Console banner (EXPERIENCE → H consoles) |
| Content | "Consola de desarrollo · datos de prueba"; virtual clock `2026-10-01T15:00:00Z` with ▸ advance (+1 h, +1 d, custom) |
| Behavior | Advancing the clock affects cooldown-dependent answers (a `Rejected` business in cooldown vs expired) |

### Section: Actor Switcher

**OBJECT ID:** `idn-explorer-actor`

| Property | Value |
|----------|-------|
| Component | Native `<select>` grouped by seed group (§3: buyers, individual sellers, mid-profile, Pending / Approved / Rejected businesses, admin) |
| Behavior | Sets the fixture session `userId`. There is no free-text role field anywhere: the actor is the only identity input (NFR-IDN-3) |

### Section: Request Pane

**OBJECT ID:** `idn-explorer-request`

| Property | Value |
|----------|-------|
| Component | [`components.api-explorer-panel`](../../../DESIGN.md) request side |
| Content | Pre-filled from the OpenAPI schema of the selected procedure |
| Behavior | Unknown keys are sent as typed so the developer can see `RequestValidationFailed` (template "Rol en el cuerpo" sends `{ "role": "business" }`) |

### Section: Response Pane

**OBJECT ID:** `idn-explorer-response`

| Property | Value |
|----------|-------|
| Component | [`components.capability-trace`](../../../DESIGN.md) for capability outputs; Decision view (outcome, reasonCode, humanMessage, citations, occurredAt) for decisions |
| Behavior | Status, latency (checks NFR-IDN-1 ≤ 50 ms p95 visually) and a "Ver JSON crudo" `<details>` toggle. The rendered `humanMessage` comes from [microcopy-es-CO.md](../../../microcopy-es-CO.md) |

### Section: Race Simulator

**OBJECT ID:** `idn-explorer-race`

| Property | Value |
|----------|-------|
| Component | [`components.race-simulator`](../../../DESIGN.md) |
| Content | Template "Carrera: perfil vs solicitud": fires FR-IDN-2 and FR-VER-1 for a fresh fixture account behind a barrier, N repetitions (default 100) |
| Behavior | The tally shows exactly-one-winner / both / neither counts. Any "both" or "neither" count > 0 turns the row `status-error` with the words "Violación de exclusividad" plus the repetition ids. Each repetition links to its two Decisions |

## Page States

| State | When | Appearance | Actions |
|-------|------|------------|---------|
| Loading | Request in flight | Response pane `components.skeleton`; "Enviando…" | Cancel |
| Empty | No procedure selected | "Elige un procedimiento a la izquierda." | Select |
| Error (transport) | Fixture API unreachable | Banner "No pudimos conectar con la API de prueba. Revisa que el servidor de desarrollo esté activo." | Reintentar |
| Success — allowed | 2xx with capabilities or `allowed` | Capability trace | Copy JSON |
| Success — refusal | Decision `rejected` | Explainability banner with humanMessage plus the code in `typography.code` | Copy JSON |
| Race running | Simulator active | Progress "37/100" with `aria-live="polite"` | Stop |
| Race result | Done | Tally line | Re-run, export CSV |

## Technical Notes

- Never built into production bundles (UX-D-5). The route is excluded by build flag, and a production request to `/dev/*` returns the standard Not-available page.
- The explorer calls the real tRPC procedures in the test composition, with the Better Auth session replaced by the fixture session (PRD §9 fakes).
- The race uses separate DB connections released by a barrier (NFR-SYS-10). The UI only displays results; the proof itself is the test suite.
