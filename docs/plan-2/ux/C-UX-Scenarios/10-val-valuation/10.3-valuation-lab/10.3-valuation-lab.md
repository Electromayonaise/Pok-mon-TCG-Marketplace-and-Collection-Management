## Overview

**Page Purpose:** Make the valuation arithmetic checkable: run the zero-baseline cases, compare the 500-entry total against an independent BigInt recomputation, property-test the conversion drift bound over 1.000 random collections, prove the acquisition step in the history series, and edit the fixture prices, FX rates and clock that drive every figure on 10.1 and 10.2.

**Success Criteria:**
- Each preset reports PASA only when every invariant it names holds; a failing run shows the first counterexample and its seed.
- Every result shows the valuation output as a Decision summary, the raw JSON, and the figures 10.1 would render from it.
- The fixture state (price table, FX table, clock) is visible and editable, and "Restablecer fixture" returns it to the seed.

**Entry Points:** The `/dev` index.

**Exit Points:** 10.1 and 10.2 of a fixture collection ("Abrir como Valentina" / "Abrir como Camila"); the `/dev` index.

## Page Sections

### Section: Console Header

**OBJECT ID:** `val-dev-header`

| Property | Value |
|----------|-------|
| Banner | "Consola de desarrollo · datos de prueba" |
| Actor switcher | Valentina (Kanto 151, «Archivo») · Camila (Mi primera colección) · anónimo (to show `NotAuthenticated`) · another collector (to show the foreign-id `CollectionNotFound`) |
| Virtual clock | +1 d · +7 d · +30 d · fecha exacta. The clock is the valuation date (`asOf`); moving it past the catalog's stale threshold marks prices stale on the next run |
| Reset | "Restablecer fixture" returns prices, FX rates, entries and clock (1 oct 2026) to the seed |

### Section: Presets (Plantillas)

**OBJECT ID:** `val-dev-presets`

| Preset | Setup | Action | Invariants checked |
|--------|-------|--------|--------------------|
| **NFR-VAL-1: base cero ×3** | Three fixture collections: empty; all entries unpriced; all entries acquired inside the period (Camila's 6 cards, acquired 10 days before `asOf`) | Trend for 7, 30, 90 and 365 days on each | `changePercent` is null with `ValuationNoBaseline` whenever `V(start) = 0`; never `NaN`, `Infinity` or a thrown division; `changeCop` is an integer; Camila's 7-day trend is finite |
| **FR-VAL-1: 500 vs BigInt** | «Archivo» (the 500-entry seed) | Value once; recompute independently with BigInt from the raw price table | `totalCop` equals the BigInt total (difference 0); `Σ entryValueCop == totalCop`; `valuedCount = 450`; 50 `notValued` (20 `ExternalEntryNotInCatalog`, 30 `NoReferencePrice`); `staleCount = 25` |
| **NFR-VAL-1: deriva ×1.000** | Generator: 1.000 random collections of 1–500 entries, quantities 1–12, several TRM dates, a mix of native-COP and FX-derived prices | Run the property test | Per collection: `Σ == total`; `|Σ fx-derived entryValueCop − convertOnce| ≤ conversionDriftBoundCop`, with `convertOnce` grouped by `fxRateDate` and the bound `floor(Σ qty of fx-derived entries / 2)`. Reports "{n} de 1.000 cumplen", the largest drift seen next to its bound, and the seed |
| **FR-VAL-4: escalón** | Kanto 151; a priced entry is added with an acquisition date 12 days before `asOf` | Fetch the history before and after adding, then after removing it | After adding: the series rises by exactly `entryValueCop` on that date and has one point per day; after removing: the step is gone from every past point |
| **FR-VAL-2: período inválido** | Any collection | Request `period = 14` | Decision rejected with `InvalidValuationPeriod`; its `humanMessage` is the §8 string |
| **NFR-VAL-2: tiempos** | «Archivo» | 50 runs each of current value + 30-day trend, and of 365-day history | p95 shown against 1.500 ms and 2.500 ms; PASA only under both |

Each preset has "Ejecutar". Every randomised run shows its seed, which can be pasted back to replay it; a failing iteration shows its collection as a downloadable fixture.

### Section: Command and Result

**OBJECT ID:** `val-dev-command`

| Property | Value |
|----------|-------|
| Inputs | Colección (fixture collections of the current actor) · periodo (7, 30, 90, 365, or a free value to provoke `InvalidValuationPeriod`) · "Valorar" / "Historial" |

| Rendered view | The lines 10.1 would show for this result (total, change, market line, coverage), so the copy can be checked against the registry |

### Section: Fixture Editors

**OBJECT ID:** `val-dev-fixtures`

| Property | Value |
|----------|-------|
| Price table (catalog stub) | `data-table` of observations: carta · fecha de observación · USD (if any) · COP · `copDerivation` (sourceNative / fxDerived) · TRM date. "+ observación" adds one at any date (time travel); deleting one shows the carried-forward effect on the next history run |

## Technical Notes

- The console runs against the catalog stub and the COL fixture named in PRD §19; it never reads production prices.
- The BigInt reference and the drift generator live in the test suite; the console calls the same code, so a PASA here is the same check CI runs.
- `conversionDriftBoundCop` is reported, never applied to a total (FR-VAL-1); this console is the only surface that shows it.
- NFR-VAL-3 (no floating point on COP) is enforced by lint in CI; the console shows the lint result next to the type test.
