## Overview

**Page Purpose:** Offer, exactly once per closed business order, to add the purchased cards to a collection, and let the buyer accept, dismiss or ignore that offer without consequence. Accepted entries carry "Comprado en TEZG" and the order link.

**Success Criteria:**
- Accepting creates one entry per order line, once, even from two tabs.
- Dismissing or ignoring creates nothing and is never nagged about.
- Every prompt's outcome is visible in the list in words.

**Entry Points:** 6.2 after "Ya recibí la carta"; Actividad tab "Sugerencias" (with the pending count).

**Exit Points:** 9.1 ("Ver en tu colección"); 6.2 ("Ver pedido"); 11.1 (the review link stays on 6.2).

## Page Sections

### Section: Inline Prompt

**OBJECT ID:** `col-prompt-inline`

| Property | Value |
|----------|-------|
| Component | `prompt-card` on 6.2, below the order facts |
| Shown when | A Pending prompt exists for this order. The prompt is created when `collections` processes the order's closing, normally within seconds; 6.2 refetches right after the close command and on its 30 s poll, so the card appears without a reload |
| Content | "¿Agregar {producto} a tu colección?" · for a bundle, the component list · select "Colección" (default: the most recently used; "General" if none exists yet) · "Agregar" · "Ahora no" |
| Accept | Re-renders as "Agregaste {producto} a «{colección}»." + "Ver en tu colección"; the live region repeats it |
| Dismiss | Re-renders as "Descartaste la sugerencia de {producto}."; nothing is created |
| Lost race | `PromptAlreadyResolved` (the other tab or the list resolved it first): the card re-renders with the actual outcome, "Ya agregaste esta carta a «{colección}»." or "Ya descartaste esta sugerencia.", naming the collection that was actually used |
| Next load | A resolved prompt is not shown on 6.2 again |

### Section: Prompt List

**OBJECT ID:** `col-prompt-list`

| Property | Value |
|----------|-------|
| Filters | Pendientes (default) · Agregadas · Descartadas, each with its count |
| Row | Product · shop · "Pedido cerrado el {fecha}" · then per status: Pending → select + "Agregar" / "Ahora no"; Accepted → "Agregada a «{colección}» el {fecha}" + "Ver en tu colección"; Dismissed → "Descartada el {fecha}" |
| Order | Newest closing first; ties by prompt id |
| Ignoring | Pending prompts have no expiry and are never re-announced; the only signal is the tab count |
| Link | "Ver pedido" → 6.2 |

### Section: Tab Count

**OBJECT ID:** `col-prompt-count`

| Property | Value |
|----------|-------|
| Value | Number of Pending prompts |
| Placement | Actividad "Sugerencias" tab, per `message-thread.unread-count` styling |

## Technical Notes

- One prompt per order (unique on `orderId`); a redelivered `OrderClosed` does nothing. Accept is a conditional `Pending → Accepted` that creates one `PlatformPurchase` entry per line (with `orderId` and `qty`) in the same transaction; a second accept gets `PromptAlreadyResolved` and creates nothing (FR-COL-7).
- The prompt stores a snapshot of the order lines; `collections` never reads or writes the order's state.
- **NFR-COL-1 proof:** an integration test drives the fixture `OrderClosed` publisher twice, then two concurrent accepts from two sessions, 100 times, and asserts 1 prompt row, 1 entry per line and one `PromptAlreadyResolved`. There is no COL H console in the page map (EXPERIENCE → IA); the ORD console 6.4 can close a fixture order to show the prompt appearing.
- Trades do not produce prompts (out of scope).
