## Overview

**Page Purpose:** Confirm "item received" once her card physically arrives, closing the Order (FR-7, CAP-22).

**User Situation:** Arrived from 4.1 by opening her recent order; the card has physically shown up.

**Success Criteria:** Confirming item-received sets `buyerItemReceivedConfirmedAt` and closes the Order — no party other than the buyer can set this confirmation (FR-7's testable Consequence).

**Entry Points:**
- ← 4.1 Orders List (opening a paid order).

**Exit Points:**
- → 4.3 Add-to-Collection Prompt (immediately after confirming item-received).

## Page States

| State | When | Appearance | Actions |
|-------|------|------------|---------|
| Default (awaiting receipt) | Paid + seller-sent, not yet buyer-confirmed | Confirm Item Received button enabled | Confirm |
| Confirming | Button tapped | Button disabled (double-submission guard) | None |
| Closed | Buyer confirmed | Timeline shows all three dots filled with timestamps; button replaced by a static "Order closed" label | View only |
| Error | Confirmation request fails | Inline error: "Couldn't confirm receipt — check your connection and try again" | Retry |

---

## Technical Notes

- This page never exposes a way to confirm receipt before the seller's own "sent" state — buyer confirmation is available regardless of seller state per the underlying data model (each of the three timestamps is independently settable), but UI copy frames the expected sequence to avoid confusion.
