## Overview

**Page Purpose:** See each order's three independently-timestamped confirmation states — paid, received-by-seller, received-by-buyer (FR-6, CAP-22).

**User Situation:** A few days later, checking in on her purchase from wherever she is — a return visit, not mid-session. Hopes to see her card is on its way without messaging the seller; worried about not knowing whether her money or card is stuck somewhere.

**Success Criteria:** Each order's tri-state status is individually visible; an abandoned/unpaid order is never lost.

**Entry Points:**
- Account menu (return visit, days after purchase).
- ← 3.2, indirectly, on successful "I Paid" confirmation.

**Exit Points:**
- → 4.2 Order Detail (tapping a paid order).
- → 3.2 Comprobante Upload (tapping "Finish payment" on an unpaid order).

## Page Sections

### Order Row (paid order)

**OBJECT ID:** `orders-list-row`

| Property | Value |
|----------|-------|
| Component | [`{components.order-status-row}`](../../../DESIGN.md) |
| Content | Item name/thumbnail, three status dots (Paid / Received-by-seller / Received-by-buyer), each independently filled once its own timestamp is set |
| Behavior | Tapping the row navigates to 4.2; each of the three states is individually queryable and displayed, never collapsed into one "complete" flag (FR-6's testable Consequence) |

### Order Row (unpaid/abandoned order)

**OBJECT ID:** `orders-list-row-unpaid`

| Property | Value |
|----------|-------|
| Content | Item name/thumbnail, "Awaiting payment" label (`colors.status-pending`), `orders-list-finish-payment-button` |
| Behavior | Tapping "Finish payment" navigates to 3.2 for this Order — implements the Phase 3A Key Decision that an abandoned purchase resumes rather than disappearing |

## Page States

| State | When | Appearance | Actions |
|-------|------|------------|---------|
| Default | Orders exist | List of rows, mixed paid/unpaid | Tap a row, or Finish payment |
| Loading | Orders still resolving | Skeleton rings in place of status dots on each row placeholder (per EXPERIENCE.md's Loading state pattern) | None |
| Empty | No orders at all | `{components.empty-state}`: "You haven't placed any orders yet" | Navigate to catalog |

---

## Technical Notes

- No filtering/sorting controls in this track's scope — the list is chronological, most-recent-first.
- The unpaid-order row is visually and structurally distinct from a paid row (no status dots shown at all until payment exists) so "Awaiting payment" is never mistaken for one of the three tri-state dots being unset.
