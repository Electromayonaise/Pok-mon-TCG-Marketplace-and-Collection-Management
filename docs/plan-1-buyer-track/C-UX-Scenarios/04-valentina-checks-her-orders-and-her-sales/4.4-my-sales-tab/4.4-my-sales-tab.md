## Overview

**Page Purpose:** Check a summary of her own open individual-seller listings and a count of pending trade offers against them (FR-9) — this scenario's climax, expressing the dual-role data model natively.

**User Situation:** Navigates here separately from 4.3, in the same account area.

**Success Criteria:** Visible to any authenticated user; shows an empty state for a user with no individual-seller listings, rather than being hidden (FR-9's testable Consequence). Final step — scenario success.

**Entry Points:**
- ← 4.3 Add-to-Collection Prompt (after accepting or declining).
- Account menu, directly, on any visit.

**Exit Points:**
- None within this track's scope — listing creation/editing and trade-offer response live in `docs/plan-1-seller-track/prd.md` (FR-S1..FR-S4).

## Page Sections

### Sales Summary

**OBJECT ID:** `my-sales-summary`

| Property | Value |
|----------|-------|
| Content | Two count rows: "Open listings: {N}," "Pending trade offers: {N}" |
| Behavior | Counts only — no listing-creation, editing, or trade-offer response from this tab; sourced live from the Seller/Business track's data (FR-S3/FR-S4) — this tab reads that data, it does not own it |

### Partial-Empty Substates

**OBJECT ID:** `my-sales-partial-empty`

| Property | Value |
|----------|-------|
| Behavior | Each count row renders independently — e.g. "Open listings: 3" alongside "Pending trade offers: 0" — rather than collapsing into a single empty state when only one count is zero |

### Fully-Empty State

**OBJECT ID:** `my-sales-empty-state`

| Property | Value |
|----------|-------|
| Component | `{components.empty-state}` |
| Content | "You're not selling anything yet" |
| Behavior | Shown only when both counts are zero (per EXPERIENCE.md's substate rule); still fully visible to any authenticated user, never hidden (FR-9's testable Consequence) |

### Error State

**OBJECT ID:** `my-sales-error-state`

| Property | Value |
|----------|-------|
| Content | "Couldn't load your sales — check your connection and try again," styled with `typography.meta` / `colors.status-error`, in place of the two count rows |
| Behavior | Shown when the underlying `listings`/`trading` query (AD-16) fails outright rather than merely running slowly — distinct from Loading (query still in flight) and from Fully-empty (query succeeded, both counts are genuinely zero). A "Try again" text action re-issues the same query without a full page reload; no retry limit or cooldown, consistent with this track's other non-security-sensitive failure states (3.2 comprobante upload). |

---

## Page States

| State | When | Appearance | Actions |
|-------|------|------------|---------|
| Default (has listings) | ≥1 open listing or pending offer | Both count rows shown independently | Navigate elsewhere; no in-tab actions |
| Fully empty | Both counts are zero | `my-sales-empty-state` | Navigate to seller-side listing creation (out of this track's scope) |
| Loading | Counts still resolving | Skeleton rows matching the summary layout | None |
| Error | The `listings`/`trading` query (AD-16) fails outright | `my-sales-error-state` | Tap "Try again" to re-issue the query |
