## Overview

**Page Purpose:** Compare individual-seller and verified-business listings for the same card, filtered by location/distance, and pick the one purchasable in-platform (FR-2, FR-4, CAP-6, CAP-17). This page's core job is the CTA distinction between the two seller types — the scenario's climax.

**User Situation:** Same session as Scenario 01, now comparing options for the card she just found trustworthy on its detail view. Hopes to buy immediately without leaving the app; worried about ending up stuck emailing or messaging a stranger with no purchase protection.

**Success Criteria:** Selects the verified-business listing and proceeds to purchase.

**Entry Points:**
- ← 1.3 Card Detail View ("Compare Listings," same session, scoped to that specific card).

**Exit Points:**
- → 3.1 Purchase Confirmation Screen (tapping "Buy Now" on a business listing).
- Contact-message confirmation (inline, this page — tapping "Contact Seller" on an individual listing; does not navigate away).

## Page Sections

### Distance Filter

**OBJECT ID:** `listing-compare-distance-filter`

| Property | Value |
|----------|-------|
| Behavior | Narrows results by distance; never excludes the catalog entry itself, only the listing set shown |

### Listing Card — Business Variant

**OBJECT ID:** `listing-compare-card-business`

| Property | Value |
|----------|-------|
| Component | [`{components.listing-card}` — `cta-business` variant](../../../DESIGN.md) |
| Content | Seller-type badge "Verified Business," seller name, rating, listing price, `{components.button-primary}` CTA "Buy Now" |
| Behavior | Tapping the CTA (or the card body) navigates directly to 3.1, scoped to this listing — this is the in-platform-purchasable path (FR-4, CAP-17) |

### Listing Card — Individual Variant

**OBJECT ID:** `listing-compare-card-individual`

| Property | Value |
|----------|-------|
| Component | [`{components.listing-card}` — `cta-individual` variant](../../../DESIGN.md) |
| Content | Seller-type badge "Individual Seller," seller name, listing price, secondary-style CTA "Contact Seller" (visually distinct from `button-primary` — a lower-emphasis affordance, since it does not complete a purchase) |
| Behavior | Tapping the CTA generates a contact message to the seller and shows `listing-compare-contact-sent-confirmation` inline on this card (CAP-6) — **resolves the Phase 3A Reviewer Gate finding that this outcome had no surface**: it does not navigate away, does not create an Order, and the card returns to its normal state after the confirmation is dismissed |

### Contact-Sent Confirmation

**OBJECT ID:** `listing-compare-contact-sent-confirmation`

| Property | Value |
|----------|-------|
| Content | Inline banner within the individual listing's card: "Message sent to seller — they'll reach out to arrange the sale" |
| Behavior | Dismissible; does not block interacting with other listings |

## Page States

| State | When | Appearance | Actions |
|-------|------|------------|---------|
| Default | Results loaded | Mixed list of business/individual listing-cards, distance-filtered | Buy Now / Contact Seller |
| Filtering | Distance filter changing | List updates in place | Continue adjusting |
| Contact sent | Contact Seller tapped | `listing-compare-contact-sent-confirmation` shown on that card | Dismiss, keep browsing |
| Defensive — listing no longer purchasable | Race condition: listing's seller-type/availability changed between page load and tap (e.g., business paused/delisted) | Inline error toast: "This listing isn't available for direct purchase right now — try another listing" | Retry with a different listing |
| Empty | No listings within the selected distance | `{components.empty-state}`: "No listings within this distance — try widening your search" | Adjust distance filter |

---

## Technical Notes

- **Resolves a Phase 3A Reviewer Gate finding on FR-4's `NotBusinessListing` rejection:** the error is prevented by design, not surfaced as a failure state — an individual listing never offers a "Buy Now" affordance in the first place, so the invalid in-platform-purchase action is never presented as available. The one residual case is a race condition (listing state changes after page load, before tap), handled by the "Defensive — listing no longer purchasable" state above, which is the only place `NotBusinessListing`-equivalent copy appears.
- CTA distinction is the load-bearing mechanism for FR-4/CAP-17 — the `cta-business`/`cta-individual` listing-card variants must never be visually interchangeable at a glance.
