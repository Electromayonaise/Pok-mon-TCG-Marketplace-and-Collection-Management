**Purpose:** Prove this page does not ship happy-path-only. Per the governing plan: "si Freya solo entrega el happy path, se lo señalo y pido los estados de error" — this wireframe is that explicit check, made visual.

## 5. Failure — three cause-differentiated variants

```
│ ┌───────────────────────────────┐ │      │ ┌───────────────────────────────┐ │      │ ┌───────────────────────────────┐ │
│ │ ⚠ That file's too big —       │ │      │ │ ⚠ We can only accept photos   │ │      │ │ ⚠ Upload didn't go through —  │ │
│ │   max 5 MB. Tap to try again. │ │      │ │   or PDFs. Tap to try again.  │ │      │ │   check your connection and   │ │
│ │                                │ │      │ │                                │ │      │ │   try again.                   │ │
│ └───────────────────────────────┘ │      │ └───────────────────────────────┘ │      │ └───────────────────────────────┘ │
      (over 5 MB)                              (wrong file type)                          (network/timeout/offline)
```

Confirm button stays disabled (grey) in all three Failure variants — no comprobante is on file yet.

## 6. Confirm sub-states (only reachable from Success)

```
Confirming:        [ Confirm I Paid (grey, spinner) ]   — uploaded file untouched underneath
Confirm failed:     ⚠ Couldn't confirm your payment — check your connection and try again
                    [ Confirm I Paid (solid, re-enabled) ]  — uploaded file still present, no re-upload needed
Confirmed:          → navigates to 4.1 Orders List
```
