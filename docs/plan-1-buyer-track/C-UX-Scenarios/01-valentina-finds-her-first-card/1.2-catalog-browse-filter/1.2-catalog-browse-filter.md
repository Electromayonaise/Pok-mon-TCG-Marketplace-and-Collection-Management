## Overview

**Page Purpose:** Filter the catalog by set and Pokémon to find a specific chased card (FR-2).

**User Situation:** Fresh off account creation, still at the release event, phone in hand, looking for one specific card.

**Success Criteria:** Finds and taps into the card she's chasing, including if it currently has zero active listings — she must still be able to see and open it (CAP-2).

**Entry Points:**
- ← 1.1 Sign Up (immediately after account creation).

**Exit Points:**
- → 1.3 Card Detail View (tapping any catalog tile).

## Page Sections

### Filter Bar

**OBJECT ID:** `catalog-filter-bar`

| Property | Value |
|----------|-------|
| Components | Set dropdown (`catalog-set-filter`), Pokémon name search (`catalog-name-filter`) |
| Behavior | Applying either filter updates results in place (no page navigation); debounced 300ms on the name field |

### Results Grid

**OBJECT ID:** `catalog-results-grid`

#### Catalog Tile

**OBJECT ID:** `catalog-tile`

| Property | Value |
|----------|-------|
| Composition | Card art thumbnail, card name (`typography.body`), set name + number (`typography.meta`), reference-price row reused from `{components.price-block}`'s reference-price sub-pattern only (no listing price shown yet — no listing is selected at this level) |
| Content when `hasActiveListings=false` | Reference-price row replaced with a `catalog-no-listings-tag`: "No active listings" (`typography.meta`, `colors.ink-disabled`) — the tile itself is otherwise fully rendered and tappable, never hidden or dimmed further |
| Behavior | Whole tile tappable → 1.3 Card Detail View, regardless of `hasActiveListings` value (CAP-2's testable Consequence) |

## Page States

| State | When | Appearance | Actions |
|-------|------|------------|---------|
| Default | Page loads, no filters | Full unfiltered catalog grid | Apply filters, tap a tile |
| Filtering | Filter value changing | Grid updates in place, no full-page loading spinner (debounced, near-instant per catalog NFR) | Continue typing/selecting |
| Results | Filters applied | Matching tiles, `hasActiveListings=false` tiles included and tagged | Tap a tile |
| Empty results | No card matches the filter combination | `{components.empty-state}`: "No cards match these filters — try a different set or name" | Adjust or clear filters |

## Technical Notes

- **Resolves a Phase 3A Reviewer Gate finding:** DESIGN.md's Empty State component description previously implied zero-listing catalog entries use the empty-state pattern. They do not — a zero-listing card is a normal, fully-interactive tile with a text tag, per EXPERIENCE.md's State Patterns. `{components.empty-state}` is reserved for this page's "no filter matches at all" case and for 1.3's full empty state, not for individual zero-listing tiles.
- Catalog browse/filter response target: ~1–2s (SPEC.md NFR).
